## 3. 测试与实际训练

Windows 本地发现 94 项测试，其中 93 项通过，1 项因缺少可选模型依赖而跳过。服务器执行全部 94 项测试，全部通过。

服务器测试包含离线 CPU 小模型的 LoRA 训练、保存和重新加载。GPU 验证另外使用已有的 0.5B 权重。

每个最终 GPU 运行包含四条候选、两条参考、一条反馈诊断和一条最终测试。最终测试没有参加评分、训练或反馈。

| 检查项 | GPU 0 | GPU 5 |
| --- | --- | --- |
| 随机分支选择 | a、c | a、c |
| 固定分支选择 | a、b | a、b |
| 每分支训练步骤 | 2 | 2 |
| 每分支实际监督 token | 24 | 24 |
| 总训练 token 消耗 | 48 | 48 |
| 总评分目标 token | 108 | 108 |
| 未释放训练预算 | 0 | 0 |
| 随机 LoRA 参数变化 L2 | 0.0330955 | 0.0330955 |
| 固定 LoRA 参数变化 L2 | 0.0323176 | 0.0323176 |
| PyTorch 峰值已分配显存 | 1,237,316,608 字节 | 1,237,316,608 字节 |

参数变化 L2 是训练后 LoRA 参数相对其初始化值的差值范数。它用于确认模型参数确实更新。

峰值已分配显存是 PyTorch 的统计值，不是整张卡的总占用。它不能直接推算 27B 模型的显存需求。

两个最终运行的冻结对照情境相同。基线反馈诊断也相同。每个产物清单及其文件重新通过了 SHA256 核验。重新打开 SQLite 后，状态与已导出的报告一致。

## 4. 诊断值的解释

反馈只有一条合成轨迹，包含 12 个有效目标 token。该轨迹的 CE 在基线为 0.477219，随机分支训练后为 0.493394，固定分支训练后为 0.461525。

这些数值确认评分、训练与重新加载之间的数据通路已经连通。样本量和训练量不足以评价筛选策略。程序没有执行自由生成任务，没有计算 benchmark 成功率，也没有验收或晋级候选模型。

## 5. 设备映射问题与修复

早期一次使用 CUDA_VISIBLE_DEVICES=5 的运行实际落在 RTX 3090 上。服务器的 CUDA 数字顺序与 nvidia-smi 不同。该运行已经结束。

原目录为 `runs/gpu5-pilot-v1`。该目录新增 device_mismatch.json，标记为 EXCLUDED_WRONG_DEVICE。原报告保留实际设备信息。这次运行不计入 5880 验证结果。

修复后，pilot 禁止数字设备绑定。程序要求单个完整 GPU UUID，并在加载模型前核对实际 UUID 和型号。相关拒绝路径已加入测试。

本记录中的两次最终运行均在修复后执行。最终检查时没有计算进程。两张 5880 均回到约 12 MiB 的基础显存占用。
