# 阶段一交付与后续接入

本文保留第一阶段的交付范围。当前 0.4.0 的实现和未完成项见 [恢复与验收接口说明](恢复与验收接口说明.md)。本文件中的“下一阶段”是当时的接入顺序。

## 1. 已实现范围

- 配置与模型引用的严格解析。
- JSONL 轨迹、训练掩码和关键片段格式。
- 数据角色、来源分组和完全相同内容的隔离检查。
- 固定策略的评分版本检查。
- 随机与固定策略共用的排序、去重和约束组批接口。
- SQLite 输入快照、对照计划、事件和成本账本。
- 重复请求去重、事务回滚和预算预留互斥。
- 当前可运行的命令入口及独立运行手册。

## 2. 证据边界

合成数据可检查数据流和异常路径。它不能证明选择有效，也不能证明真实模型的 tokenizer、模板或任务环境正确。

当前组批采用完整轨迹的贪心方案。当前持久化保存完整 JSON 快照，适合第一阶段的小规模输入。大数据集接入时，应改用经过内容校验的外部数据产物及不可变清单，并保持状态数据库作为唯一写入来源。

数据使用记录目前来自初始化快照。计划生成不把轨迹标为已训练。实际逐批使用回写、候选模型产物登记和晋级事务将随真实训练后端接入。

当前成本账本覆盖监督 token、评分 token 和评估调用次数。真实后端接入时，还需增加上下文 token、训练步数、设备时间和控制调用成本。现有账本不能单独证明完整系统的算力效率。

## 3. H200 目标

用户提供的目标为 8×H200，每张 144 GB。配置来源为 user_reported。当前没有设备连接信息，也没有验证实际显存、CUDA、通信拓扑或驱动。

建议后续先验证单个训练作业，再验证八卡执行。随机与固定策略分支应顺序运行并共享起点，避免设备竞争造成比较差异。

暂不固定 LoRA 秩、学习率、长度或批量。模型规模、数据长度分布和训练窗口确定后，再测量显存与吞吐。八个目标进程只是部署草稿，不代表已经完成分布式适配。

## 4. 下一阶段

1. 确定首个模型和 tokenizer、模板版本。
2. 确定一个可重置的编程任务环境与数据来源。
3. 实现真实分词与掩码映射，并验证错误动作不进入监督。
4. 接入教师强制评分，使用同一模型和模板生成有效 NLL、熵与 CDF。
5. 接入 LoRA 训练后端，验证实际监督量、恢复状态与模型产物。
6. 接入独立任务评估并输出配对结果。
7. 在同一起点运行随机与固定策略的等预算训练比较。

接入真实训练时，应优先验证预算、实际使用回写和中断恢复。随后再接入 Agent 决策、经验检索与自动晋级。

## 5. 不可跳过的接入检查

| 接入项 | 要求 |
| --- | --- |
| 分词 | 参考文本与 token 位置可复现；模板与模型引用一致 |
| 监督 | 用户和工具 token 不进入损失；错误动作只保留上下文 |
| 训练 | 新尝试重建优化器与学习率计划；同次中断恢复完整状态 |
| 计量 | 记录实际参与损失的 token；重复遍历和失败尝试均计入 |
| 模型产物 | 完整写入并核验后才登记；未登记产物不能晋级 |
| 比较 | 共享模型、候选、预算与评估条件；保存所有分支结果 |
| 验收 | 统计规则完整后才启用；证据不足不自动接受 |
