# 代码结构与维护

0.7.0 按功能组织源码。原有 48 个业务模块移入 9 个子包。每个模块保留原文件名，便于对照历史代码。项目命令、配置格式、数据库格式和训练约定保持不变。

## 1. 从功能查找代码

例如，需要增加一种筛选策略时，先查看 `curation/selection.py`。需要接入新模型时，先查看 `models/backends.py` 和 `models/hf_backend.py`。命令行只负责解析参数和调用接口，不承担筛选或训练规则。

```text
rsi/
  __init__.py             包版本与旧导入兼容注册
  __main__.py             python -m rsi 入口
  _compat.py              旧模块路径到新模块路径的明确映射
  _paths.py               包目录与源码工程目录
  configuration/          配置类型、校验与实验合同
  datasets/               轨迹、标签、数据导入与分词
  curation/               选择、组批、策略、历史与调度
  models/                 后端接口、模型执行、评分与诊断
  storage/                状态、账本、产物、检查点与源码身份
  evaluation/             任务格式、逐任务评估与验收
  execution/              宿主隔离编排与沙箱启动器
  workflows/              评分、训练、恢复、评估与报告流程
  commands/               命令参数和输出
```

## 2. 模块归属

| 子包 | 模块 | 主要边界 |
| --- | --- | --- |
| `configuration` | `validation`、`settings`、`contracts` | 解析和校验输入；不启动模型或写运行状态 |
| `datasets` | `data`、`labels`、`tokenization`、`mbpp`、`dataset_import`、`data_compile`、`python_diagnostics` | 提供轨迹和标签；数据编译复用已有分词接口 |
| `curation` | `selection`、`packing`、`inspection`、`policy`、`policy_selection`、`history`、`feedback`、`dispatch`、`comparison`、`selection_io`、`selection_demo` | 策略与调度纯计算不写库；文件发布集中在 `selection_io` |
| `models` | `backends`、`hf_backend`、`model_inputs`、`devices`、`scoring`、`diagnostics` | 后端执行模型；导入模块不加载模型依赖或占用 GPU |
| `storage` | `artifacts`、`leases`、`schema`、`state`、`checkpoints`、`provenance` | 保存并核对状态、成本和产物；不执行训练 |
| `evaluation` | `coding_tasks`、`python_tasks`、`bounded_python`、`coding_evaluation`、`isolated_evaluation`、`acceptance` | 区分任务结果与基础设施错误；保留逐任务证据 |
| `execution` | `sandbox`、`sandbox_worker` | 宿主只编排隔离；外部代码在沙箱内执行 |
| `workflows` | `pilot`、`real_run`、`training_run`、`scoring_run`、`evaluation_run`、`reporting` | 连接业务接口、外部执行和状态提交；不复制规则 |
| `commands` | `cli`、`selection_cli` | 参数解析、调用接口和退出码 |

这是按职责划分的目录，不是严格的单向依赖层。现有字段接口仍由所属模块定义。扩展时先复用这些接口，不建立重复的数据类型。

第二阶段模块沿用同一划分：

| 子包 | 第二阶段模块 |
| --- | --- |
| `configuration` | `training_config`：显式导出已校验合同 |
| `datasets` | `training_inputs`：标准消息编译与标签、技能证据映射；`content_identity`：实际任务内容与来源问题的规范化身份 |
| `models` | `model_resolution`、`training_mock`：模型定位和显式测试后端 |
| `storage` | `execution_artifacts`：执行清单、依赖快照与缓存身份 |
| `evaluation` | `fit_evaluation`、`execution_evaluation`、`task_adapters`、`round_feedback`：整条及技能拟合、逐任务执行和配对反馈；`agent_tasks`：多步 Agent 与环境协议、轨迹记录和缓存证据核验 |
| `workflows` | `training_compile`、`execution_plan`、`attempt_run`、`validation_run`、`benchmark_run`、`training_demo`：冻结输入、单次训练、双路验证与独立最终测试 |
| `commands` | `training_cli`：第二阶段独立命令 |

第二阶段也直接调用 `storage.provenance.source_manifest`，递归覆盖子包中的源码。旧的第二阶段根目录导入只通过 `_compat.py` 映射到同一模块对象。

## 3. 导入约定

新代码直接导入实现模块。例如：

```python
from rsi.configuration.contracts import ExperimentContract
from rsi.curation.selection import FixedSelector, build_batch
from rsi.storage.state import StateStore
```

子包的 `__init__.py` 只说明职责。不要在其中集中导入业务模块。不要让基础校验命令依赖 torch、transformers 或 peft。

`rsi/_compat.py` 列出旧路径和新路径。旧路径通过延迟加载指向同一个模块对象。例如，`rsi.selection` 与 `rsi.curation.selection` 使用同一个实现。旧脚本的导入、异常类型和测试补丁继续有效。`python -m rsi.cli` 也保留兼容。

新代码和新测试使用新路径。现有测试中的旧路径用于检查兼容行为。不要增加星号转发文件，也不要复制实现来维持旧路径。

`sandbox_worker` 是独立沙箱启动器，不是宿主 Python 接口。它的新位置是 `rsi/execution/sandbox_worker.py`。宿主通过 `sandbox.py` 定位该文件。不要在宿主导入该模块或直接执行它。

## 4. 新功能的放置方法

| 新功能 | 首先修改的接口 | 需要复用的规则 |
| --- | --- | --- |
| 新数据集 | `datasets/dataset_import.py` 的来源格式和 `datasets/data_compile.py` | 来源哈希、数据角色、完整轨迹和分词校验 |
| 新筛选策略 | `curation/selection.py` 的选择器接口 | 共用组批、预算、配额和随机种子 |
| Agent 调度 | `curation/dispatch.py` 和 `curation/policy.py` | 补丁白名单、冻结身份、完整重校验和证据边界 |
| 新模型或训练后端 | `models/backends.py` | 实际消耗、失败传播、产物身份和检查点 |
| 多卡执行 | `models` 中的新后端和 `workflows/training_run.py` | 相同训练合同、成本账本和恢复边界 |
| 新任务评估 | `evaluation` 中的任务与后端接口 | 相同任务分母、逐任务证据和最终测试隔离 |
| 新命令 | `commands/cli.py` 或对应命令适配器 | 调用现有业务接口；不在命令中复制流程 |

1. 先读取相关实现和测试。
2. 确定输入、输出、副作用和失败条件。
3. 在所属子包实现功能。
4. 在 `tests/` 增加对应行为测试。
5. 更新接口和运行手册。
6. 运行完整测试和相关命令流程。

控制 Agent、多卡和自动晋级仍需单独实现。能力测评已有可注入的 Agent 与环境协议；真实 Agent 后端、工具和环境仍需接入。目录名称不代表这些功能已实现。

## 5. 源码身份与恢复

`storage/provenance.py` 递归记录 `rsi/` 下所有 Python 源码的相对路径与 SHA256。它排除 `__pycache__`。训练请求、运行环境和评估证据共用该清单，避免漏掉子目录变化。

本次迁移改变了源码身份。0.7.0 不恢复 0.6.0 或更早提交创建的训练运行。需要恢复旧运行时，保留原运行目录，并使用当时的源码提交。不要覆盖旧清单，也不要清除成本账本后重跑。

新版本内的恢复仍要求冻结输入和源码身份一致。`tests/test_package_layout.py` 检查嵌套源码变化后拒绝旧检查点。

## 6. 执行与验证范围

建议从克隆后的工程根目录运行。`make-selection-fixture` 的默认模板使用工程内的 `configs/smoke.json`。当前安装包不包含工程配置和示例。只安装 wheel 后，不能假定这些文件存在。该演示命令需要源码工程中的配置。其他接受配置路径的命令需要显式传入实际文件。

迁移测试检查旧导入、新导入、测试补丁、命令入口、源码身份和隔离启动器位置。常规回归测试继续检查配置、数据、筛选、状态和命令行为。

模型测试需要可选模型依赖。实际隔离集成测试需要 Linux 和明确启用。基础回归通过不代表 GPU 训练或 Linux 隔离已重新验证。历史训练记录继续保留其原版本和原测量范围。
