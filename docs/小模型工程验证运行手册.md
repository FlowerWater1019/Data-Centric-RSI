# 小模型工程验证运行手册

公开仓库说明：机器地址、服务器账号和设备 UUID 使用占位值。路径需按目标机器填写。历史结果数字保持不变。

## 1. 目的与范围

本手册用于验证真实分词、模型评分、单卡 LoRA 训练和产物重新加载。程序使用合成编程轨迹。

该流程会真正更新模型参数。它不执行编程任务 benchmark，也不证明筛选能力提升。不要把反馈 CE 的变化解释为任务成功率变化。

本次已由代理运行工程验证。你现在无需重复运行。下面步骤用于复核或后续维护。

## 4. 检查设备与软件

先查看显卡和当前计算进程。

```bash
nvidia-smi
nvidia-smi --query-gpu=index,name,uuid,memory.used --format=csv
```

确认物理 GPU 0 或 GPU 5 当前可用。不要停止其他人的任务。当前空闲状态会变化，旧报告不能替代现场检查。

然后执行基础测试。此命令隐藏 GPU，使用 CPU 检查软件。

```bash
CUDA_VISIBLE_DEVICES='' HF_HUB_OFFLINE=1 TRANSFORMERS_OFFLINE=1 \
  "$RSI_PYTHON" -m unittest discover -s tests -v
```

预期最后显示 OK。当前服务器环境还会执行一个离线随机小模型训练测试。它不下载模型。

## 5. 运行物理 GPU 0 上的验证

执行以下命令。输出目录必须尚不存在。

```bash
CUDA_VISIBLE_DEVICES=GPU-REPLACE_WITH_FIRST_DEVICE_UUID HF_HUB_OFFLINE=1 TRANSFORMERS_OFFLINE=1 \
TOKENIZERS_PARALLELISM=false OMP_NUM_THREADS=4 \
  "$RSI_PYTHON" -u -m rsi pilot \
  --config configs/pilot.json \
  --model-path "$RSI_MODEL" \
  --output runs/manual-gpu0-001 \
  --device cuda:0
```

CUDA_VISIBLE_DEVICES 使用物理 GPU 0 的完整 UUID。进程内该设备编号为 cuda:0。程序在加载模型前核对 UUID 与型号。不要用数字 0 替代 UUID。

程序先计算本地模型文件哈希。随后导入消息、评分、生成计划并依次训练两个分支。最后重新加载两个 LoRA 产物并计算诊断 CE。

预期最后输出 training_status 为 COMPLETED，以及 report.json 的路径。task_execution 必须仍为 NOT_RUN。

如需再次执行，改用新输出目录，例如 runs/manual-gpu0-002。程序不会覆盖旧结果，也不会自动恢复旧运行。

## 6. 在物理 GPU 5 上复核

使用以下命令。该步骤仍是单卡运行。

```bash
CUDA_VISIBLE_DEVICES=GPU-REPLACE_WITH_SECOND_DEVICE_UUID HF_HUB_OFFLINE=1 TRANSFORMERS_OFFLINE=1 \
TOKENIZERS_PARALLELISM=false OMP_NUM_THREADS=4 \
  "$RSI_PYTHON" -u -m rsi pilot \
  --config configs/pilot.json \
  --model-path "$RSI_MODEL" \
  --output runs/manual-gpu5-001 \
  --device cuda:0
```

该 UUID 指定 nvidia-smi 中的物理 GPU 5。它在进程内映射为 cuda:0。不要把 UUID 改成数字 5，也不要把 device 参数改成 cuda:5。服务器的 CUDA 数字顺序与 nvidia-smi 不同。

分别通过两张卡的单卡验证，不代表已经验证双卡分布式训练。

## 7. 检查结果

以 manual-gpu0-001 为例，执行以下命令。

```bash
"$RSI_PYTHON" -m rsi status \
  --db runs/manual-gpu0-001/state.sqlite3 --run-id training
```

检查这些内容。

| 内容 | 预期 |
| --- | --- |
| 顶层 training_status | COMPLETED |
| training_tokens.used | 与两个分支实际监督量之和一致 |
| training_tokens.reserved | 0 |
| 训练使用事件 | 包含真实 data_id、版本、掩码与步骤 |
| accepted_model | 仍为初始模型；本流程不验收晋级 |
| report.json 的 task_execution | NOT_RUN |
| report.json 的 distributed_validation | NOT_RUN |

scoring 运行单独保存评分成本。

```bash
"$RSI_PYTHON" -m rsi status \
  --db runs/manual-gpu0-001/state.sqlite3 --run-id scoring
```

产物位置如下。

| 文件或目录 | 内容 |
| --- | --- |
| report.json | 汇总状态、选择结果、诊断与成本 |
| environment.json | Python、依赖版本与实际设备 |
| model_identity.json | 本地模型文件哈希 |
| code_identity.json | 源码、配置和源数据哈希 |
| contract.json | 本次冻结配置 |
| tokenized.json、scored.json | 真实分词结果与评分结果 |
| random/adapter、fixed/adapter | 两个独立 LoRA 产物 |
| random/training.json、fixed/training.json | 步骤损失、实际监督量、参数变化量 |
| 各分支 manifest.json | 产物文件校验值 |
| 各分支 optimizer_state.pt | 保存的训练状态；恢复接口尚未开放 |

same_batch 为 true 时，两个策略选择了相同批次。程序保留该事实，不修改样本制造差异。

## 8. 失败处理

如果出现失败，保留输出目录、日志、failure.json 和 state.sqlite3。不要手工改数据库状态。

如果设备检查失败，核对 UUID 和配置中的 expected_device_name。不要删除检查来继续运行。

如果路径不存在，核对模型与 Python 路径。如果输入超过长度，修订新配置并使用新目录。不要通过静默截断绕过检查。

如果进程在训练中中断，当前版本不能自动恢复。已有成本继续保留。重跑必须使用新目录，并作为新的尝试记录。设备异常期间尚未写入账本的计算量可能未知。

正式研究实验需要先接入真实任务评估、完整恢复和验收规则。当前不需要你运行 27B 或八卡实验。
