# PR #2 审查修复与 Agent 接口验证

本轮在 `feat/training-validation` 修改代码。起点提交为 `0171d147291b453d431cf0c9db7333aa58662950`。本轮没有提交或推送远程。运行产物保存在忽略的 `runs/` 下。

## 行为变化

1. 执行缓存逐题核对实际冻结套件。核对数量、顺序、任务 ID、分组、技能、种子和公开输入。缓存还核对调用意图、生成文本、逐题结果和判分证据。重建文件清单不能绕过这些业务校验。受限表达式判分可以安全重算；真实环境动作不会因缓存校验而重放。
2. 内容指纹由实际任务计算。Python 内容按语法树规范化。公开问题使用统一 Unicode 与空白规则，与来源消息采用可比较的身份。相同公开问题即使更换编号、申报指纹或测试，也不能进入独立最终套件。默认反馈题与最终题已分开。
3. 任务套件升级为 `execution-suite-v2`。执行报告升级为 `execution-evaluation-v2`。旧格式明确拒绝，不静默改写旧运行。迁移步骤见[接口说明](单次训练与双路验证接口.md)。
4. 新增多步 Agent 环境协议。策略根据任务、观察和历史选择动作。环境执行动作，再按私有判定器检查最终状态。执行器保存动作与观察，并在失败时释放环境资源。反馈验证与独立 benchmark 共用执行核心。
5. 拟合计算范围保持为本次冻结训练批次中全部实际 SFT loss 位置。用户确认的“全 token”指这个范围。它不扩大到未监督的上下文。技能片段从同一次逐 token 前向结果映射，不额外执行前向。新增回归测试核对批次成员、顺序、掩码、调用次数和技能统计。

内容检查只发现已知规范化文本重叠。它不能证明没有语义改写或未知来源污染。真实 Agent 后端必须实现超时、工具权限、环境隔离和模型绑定。协议本身不建立可信容器。

最后一轮交付复核结果：313 项，298 项通过，15 项跳过，无失败。完整复核耗时 80.816 秒，Python 退出码为 0。新增测试覆盖以下行为：

- 未知、遗漏、额外和重排任务，以及分组、技能、种子和公开输入变化。
- 重建清单后，调用、生成、判分及 Agent 动作证据仍须一致。
- 相同内容换编号或指纹、相同问题换测试、训练来源问题重叠。
- Python 排版、注释和测试顺序的内容规范化。
- 本次训练批次的拟合输入及技能片段映射。
- 多步 Agent 成功、不同有效动作路径、动作上限、环境异常、资源释放和缺少后端。
- Agent 缓存复用不重放动作，反馈与独立最终测评共用执行核心。
- 环境主动终止、部分得分、无技能任务完整分母、非法判定分数与 Agent 模型绑定不一致。

15 项跳过包括 7 项可选模型依赖测试和 8 项 Linux 隔离集成测试。本机没有执行真实 tiny 参数更新、目标 27B 或 GPU 作业，也没有执行 Linux 沙箱集成。不能用 mock 结果替代这些检查。

直接运行的完整回归已得到上述通过结果。收集真实退出码时，第一次日志包装仅设置 `PYTHONIOENCODING=utf-8`，没有统一 Python 默认文本编码，触发了 3 个旧命令子进程测试的解码异常。随后日志脚本同时设置 `PYTHONUTF8=1`，使父子进程一致。该问题属于本地验证脚本的环境设置；没有通过删改产品测试来避开失败。
