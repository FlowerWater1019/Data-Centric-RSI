# 筛选链路演示运行手册

## 运行范围

命令从仓库根目录执行，只依赖 Python 标准库。演示不访问网络、不加载模型、不使用 GPU。运行产物保存在 runs，不提交到仓库。

所有标签与反馈均为合成值。训练与任务执行状态均为 NOT_RUN。演示只检验软件连接、可追溯性和策略影响。

## 完整演示

先确认以下输出目录不存在。程序默认拒绝覆盖已有目录。
演示输出目录不能位于 fixture 目录内部。

```text
python -m rsi make-selection-fixture --output runs/selection-fixture --seed 42 --settings examples/selection_fixture.settings.json
python -m rsi selection-demo --fixture runs/selection-fixture --output runs/selection-demo
```

生成器建立 10 条 candidate 和 2 条 reference，总数为 12。每条 candidate 有 4 个监督 token。分词状态明确为 demo。字符 token、位置、掩码和文本哈希由生成内容计算。

技能通过局部 random.Random(seed) 分配。默认每条一个技能。修改 examples 设置可改变技能列表和标签数。生成器不会重标注现有真实轨迹。参考分数和候选分数均为 fixture。百分位通过已有 attach_scores 和 empirical_percentile 计算。原始模拟数值保存在 scores.fixture.json。

selection-demo 先核验 fixture 清单。它执行首次筛选，计算实际 batch_id，再把该 ID 写入反馈、调度和批次历史。程序不会只在内存中修改身份。它随后应用补丁并执行第二次筛选。

## 独立命令

先检查输入。模拟标签需要显式开关。

```text
python -m rsi validate-selection --config runs/selection-fixture/config.json --data runs/selection-fixture/trajectories.jsonl --labels runs/selection-fixture/labels.jsonl --ontology runs/selection-fixture/ontology.json --policy runs/selection-fixture/policy.json --allow-synthetic-labels
```

validate-selection 不组批。随后可独立选择第一批。

```text
python -m rsi select-with-policy --config runs/selection-fixture/config.json --data runs/selection-fixture/trajectories.jsonl --labels runs/selection-fixture/labels.jsonl --ontology runs/selection-fixture/ontology.json --policy runs/selection-fixture/policy.json --allow-synthetic-labels --output runs/selection-before
```

使用完整演示已经落盘的绑定身份，独立应用同一调度。

```text
python -m rsi apply-dispatch --policy runs/selection-fixture/policy.json --dispatch runs/selection-demo/dispatch.fixture.json --feedback runs/selection-demo/feedback.fixture.json --ontology runs/selection-fixture/ontology.json --batch-history runs/selection-demo/batch_history.json --output runs/selection-application
```

对同一输出目录重复执行该 apply-dispatch 命令，返回 already_applied。输出存储单元以 --output 指定的目录为范围。同一存储单元中的同 ID 不同请求会报冲突；不建立跨目录的全局调度数据库。新策略保存在 policy.after.json，父策略保存在 policy.parent.json。两者不会相互覆盖。

最后使用新策略再次筛选。

```text
python -m rsi select-with-policy --config runs/selection-fixture/config.json --data runs/selection-fixture/trajectories.jsonl --labels runs/selection-fixture/labels.jsonl --ontology runs/selection-fixture/ontology.json --policy runs/selection-application/policy.after.json --batch-history runs/selection-demo/batch_history.json --allow-synthetic-labels --output runs/selection-after
```

存在历史调度时，apply-dispatch 可接收 --dispatch-history 和 --feedback-history。两者分别为调度数组和反馈数组。deferred_batch_ids 必须通过 --batch-history 解析。未知批次会失败。

## 产物与失败处理

```text
runs/selection-demo/
  manifest.json
  inputs/                       # 完整原始 fixture，保留父策略
  before/selection_report.json
  before/batch.json
  batch_history.json
  feedback.fixture.json         # 已绑定实际 batch_id
  dispatch.fixture.json         # 已绑定实际 batch_id
  policy.after.json
  dispatch_application.json
  after/selection_report.json
  after/batch.json
  comparison.json
  feedback_rates.json
  report.md
```

manifest 对全部输入与输出文件记录 SHA256，并用仓库 digest 规则生成清单 content_id。报告没有依赖绝对路径或墙钟时间的决定性字段。同输入的两次演示产生相同清单身份。

输出采用同级临时目录构建。程序先持有父目录单写者锁，再写文件，最后写清单并核验，随后重命名发布。普通异常会清理本次临时目录。进程被强制终止时可能留下 `.pending-*` 目录，但不会将其作为完整输出读取。程序不自动重用该目录，也不据此回滚正式训练状态。该机制不承诺突然断电后的文件系统持久性，不支持网络文件系统。

输入错误、过期评分、预算失败和配额失败都返回非零，stderr 包含位置或失败类别。失败不发布目标目录。纯选择接口可返回 BUDGET_FAILED 或 QUOTA_FAILED 报告，供下一阶段编排读取。
