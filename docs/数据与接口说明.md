# 数据与接口说明

## 1. 格式与验证范围

配置使用 UTF-8 JSON。轨迹使用 UTF-8 JSONL，每行一个完整对象。程序拒绝重复 JSON 字段、NaN、Infinity 和未声明字段。

代码中的解析函数是当前可执行的格式定义。JSON 示例见 configs 和 examples 目录。方案文档中的 JSON 用于说明研究流程，不是可以直接送入程序的完整数据文件。

当前验证范围是结构与声明的一致性。程序不验证外部证据内容，不重新执行代码，也不重新调用真实分词器。语义近重复、错误来源分组和伪造证据不能仅靠当前结构检查排除。

## 2. 实验配置

| 字段 | 含义 |
| --- | --- |
| schema_version | 当前为字符串 1.0 |
| contract_id | 实验约定编号 |
| purpose | smoke 为演示；draft 为真实数据准备草稿；research 为正式实验 |
| seed | 非负整数，用于可复现的选择顺序 |
| model | 检查点、基座、适配器、分词器和模板版本 |
| skills | 允许使用的技能名称 |
| selection | 单批监督 token 预算、允许不足量、各技能最低覆盖 |
| scoring | 评分规则、参考组和 CDF 版本 |
| fixed_strategy | 梯形偏好、权重和技能偏好 |
| hardware | 目标设备声明及来源 |
| training | 后端、目标进程数、精度及待配置训练参数 |
| acceptance | 待配置的主指标、保持容忍、统计与复测条件 |
| budgets | training_tokens、scoring_tokens、evaluation_calls 三项独立预算 |
| allow_feedback_overlap | 是否允许反馈诊断与反馈执行共用分组 |

权重必须非负且总和为 1。偏好区间必须满足 support_left < preferred_left <= preferred_right < support_right。所有端点位于 0 到 1。

技能覆盖可以重叠。因此，程序不要求各技能最低覆盖比例之和小于或等于 1。程序在真实组批后检查每项配额。

research 配置在存在关键空值时拒绝加载。即使填写了空值，当前版本仍因训练后端尚未实现而拒绝正式实验。后续接入真实后端时，还必须扩展完整的验收和运行环境配置。

## 3. 轨迹字段

| 字段 | 含义 |
| --- | --- |
| data_id、version | 数据身份与不可混淆的内容版本 |
| role | candidate、score_probe、reference、feedback_diagnostic、feedback_execution 或 final_test |
| split_group | 隔离分组，例如仓库或任务族 |
| duplicate_group | 已识别的重复数据组 |
| text、text_sha256 | 已按模板组织的完整参考文本及其 UTF-8 SHA256 |
| skills | 轨迹技能标签 |
| quality | pass/fail/unknown、证据编号、结构有效性和泄漏状态 |
| tokenization | 分词状态、模型模板版本、token IDs、字符位置、角色和正确性 |
| supervision | 训练掩码版本与逐 token 布尔掩码 |
| diagnostic_spans | 技能、token 区间、字符区间、证据编号及诊断版本 |
| usage | 既往真实训练使用、尝试编号、累计监督量和继承链状态 |
| scores | 模型及数据版本、原始 NLL/熵、百分位；可以为 null |

同一角色内可以存在同任务组的多条数据。candidate 与任何保留角色共用 split_group、duplicate_group 或完全相同内容时，程序拒绝。

score_probe 与 reference 可以共用分组。feedback_diagnostic 与 feedback_execution 只有在配置明确允许时可以共用。final_test 与其他角色始终隔离。

## 4. 位置与掩码

所有位置使用从 0 开始的左闭右开区间。字符位置以 Python 字符串索引计数，不是 UTF-8 字节位置。

token_ids、offsets、roles、correctness 和 loss_mask 必须具有相同长度。字符位置必须有序且在文本范围内。特殊 token 可以使用零宽字符位置。

loss_mask 标记未移位的目标 token 位置。首个 token 必须不参与损失。训练后端需要对预测与目标正确移位，并按有效目标数计量，不能重复移位或把首个位置计入预算。

只有 role 为 assistant 且 correctness 为 valid 的 token 可以进入正向监督。工具返回、用户输入、错误动作和未知动作不参与损失。

诊断片段的两端必须对应其 token 区间的字符两端。该片段至少包含一个有效监督 token。后续诊断后端必须取诊断片段与训练掩码的交集。

一条轨迹可以具有多个重叠诊断标签。训练监督量按训练掩码计数一次。技能覆盖仍按带技能标签的轨迹所贡献的有效监督 token 计算。

tokenization.status 为 demo 时，仅允许 smoke 配置。verified 是上游处理的声明，不是本程序自动获得的结论。不能仅修改该字段就声称已经核验真实分词。

## 5. 评分有效性

固定策略要求所有可选候选具有当前分数。程序核对检查点、轨迹、训练掩码、评分规则、参考组和 CDF 版本。

随机排序不需要 NLL 或熵。它仍受角色、质量、继承链、监督量和组批约束限制。

当前代码不会产生新分数。examples 中的分数是手工演示值。评分缓存刷新和 CDF 计算将在后续阶段实现。

## 6. 选择器与组批

Selector.rank 接收 SelectionContext，返回同一可选集合的排序。选择器不能自行删减数据、修改监督量或降低质量门槛。

RandomSelector 先按 data_id 排列候选，再按固定种子打乱。FixedSelector 使用定稿版的梯形效用、最大技能匹配和固定加权公式。相同分数按 data_id 决定顺序。

两者复用同一个贪心组批器。组批器按排序选择完整轨迹，跳过重复组、重复内容及超预算轨迹。最后检查预算下界和技能覆盖。

当前组批器不搜索所有组合。失败表示没有找到合法批次，不表示已经证明无解。程序不自动改变配额、重复数据或切碎轨迹。

BatchManifest 保存原始选择顺序。fingerprint 则对数据标识、版本、掩码、内容校验值和使用次数排序后计算，用于识别相同批次。

## 7. 状态与成本接口

StateStore.initialize 冻结配置和数据。相同 run-id 与相同内容可重复调用。内容不同则拒绝。

StateStore.prepare_comparison 只允许 controlled 运行。两个计划在同一事务中保存。任何一组失败时，不留下半个对照计划。

comparison.build_comparison 承担对照计划计算。该函数返回 ComparisonPlan，不操作数据库。StateStore 负责状态检查、重复请求处理和提交。

StateStore 默认允许创建空库。create=False 只打开已有文件。read_only=True 以只读连接打开已有文件。status 和 export 使用只读连接。snapshot 在读事务中获取一致快照，不提前申请写锁。读事务仍受 SQLite 本身的锁规则约束。

程序先检查已有数据库的版本、表和列。不支持的版本、缺少元数据或结构不完整时，程序拒绝打开。程序不会自动补表。新库的建表和版本登记在同一事务中提交。

StateStore.reserve 预留作业预算。它检查已消耗与已预留之和。StateStore.consume 记录实际消耗，并按实际量减少预留。StateStore.release 释放尚未使用的预留，不返还实际消耗。

预留编号和消耗事件编号都具有运行内唯一性。相同编号与相同内容重复提交时，不重复记账。相同编号与不同内容提交时，程序拒绝。

实际消耗超过预留时，程序仍保存消耗事实，并将运行标为 execution_error。此后禁止新预留和新计划。恢复策略需要后续调度层处理，不能擦除成本来恢复。

这些账本接口是后续执行后端的接入点。当前命令流程只生成计划，不调用实际消耗接口。测试中的账本记录与用户运行数据库隔离。

## 8. 训练与评估接口

TrainingRequest 保存 run-id、attempt-id、实验约定校验值、起始 ModelRef、BatchManifest、TrainingConfig 和可选恢复产物。

TrainingBackend.train 的未来返回值为 TrainingResult。该类型包含候选模型、模型产物、实际监督量和可选诊断产物。ArtifactRef 统一保存产物路径及 SHA256。当前 UnimplementedTrainingBackend 始终明确报错。

EvaluationBackend.evaluate 接收 EvaluationRequest。请求包含模型、带校验值的任务清单和种子。返回值为 EvaluationResult，包含 MetricResult 列表和逐任务证据产物。每个指标记录名称、值、样本量和指标定义。指标定义必须说明聚合单位或分母。

这些类型规定接口字段。它们不执行文件校验，也不构成验收器。实际适配器接入时，必须校验产物、非有限指标、样本量和失败任务处理。任务清单内容、错误恢复及统计验收仍待实现。

当前没有接受模型的写入接口。状态报告只返回初始化的已接受模型引用。controlled 计划不能修改在线运行的模型或经验。

## 9. Python 接口变更：0.2.0

本次变更保持命令参数、JSON 1.0 和数据库版本 1。内部 Python 调用方需要使用明确字段。

| 原调用 | 当前调用 |
| --- | --- |
| contract.training["world_size"] | contract.training.world_size |
| contract.hardware["gpu_count"] | contract.hardware.gpu_count |
| record.scores["nll_percentile"] | record.scores.nll_percentile；先确认 scores 非空 |
| batch.items[0]["data_id"] | batch.items[0].data_id |
| batch.model["checkpoint_id"] | batch.model.checkpoint_id |
| TrainingResult.artifact_path、artifact_sha256 | TrainingResult.artifact.path、artifact.sha256 |
| evaluate(model, task_manifest, seed) | evaluate(EvaluationRequest(...)) |

record.raw 返回独立副本。配置中的动态技能映射与预算映射只读。修改配置、轨迹或分数时，重新解析新的原始输入。不要修改已校验对象。

BatchManifest、ComparisonPlan 和 ValidationReport 提供 to_dict()。该方法生成独立的 JSON 数据。其他字段类型可以使用 validation.to_json_value() 转换。数据类构造器不替代外部输入校验；实验配置与轨迹应继续使用 parse 或 validate_dataset。
