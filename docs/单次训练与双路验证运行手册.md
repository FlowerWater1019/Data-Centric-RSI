# 单次训练与双路验证运行手册

从仓库根目录执行命令。输出使用新的目录。程序不下载模型、不推送远程、不启动控制 Agent、不自动晋级。

当前任务示例使用 `execution-suite-v2`。内容指纹必须由实际任务计算。旧 v1 套件和执行报告不能直接复用；不要改写已有运行产物。迁移规则见[接口说明](单次训练与双路验证接口.md)。

下面的 CLI 演示验证代码生成适配器。多步 Agent 测评使用可注入的策略和环境接口，见 [Agent 能力测评接口](Agent能力测评接口.md)。CLI 尚未配置真实 Agent 后端。没有 runner 时，Agent 套件会明确报错。

## 1. 最短离线演示

```text
python -m unittest discover -s tests -v
python -m rsi training-validation-demo --output runs/training-validation-demo --mode mock --device cpu
```

mock 演示使用标准消息格式，重新执行测试分词、位置映射和评分编排。它冻结第一阶段选中的四条轨迹，共 136 个字符监督 token。mock 不更新真实参数，拟合下降是预设测试值。它不能证明模型训练有效。

演示先在训练前测量父模型拟合。训练后，双路编排核验并复用该完整阶段。它再测量候选拟合和父候选自由执行，最后单独运行最终套件。

优先查看以下文件：

| 文件 | 读取目的 |
| --- | --- |
| `demo_report.json` | 确认模式、来源、token 量和完成状态 |
| `compiled/provenance.json` | 区分分词方式、数据性质和标签来源 |
| `selection/batch.json` | 查看实际训练成员和顺序 |
| `attempt/plan.json` | 查看冻结身份和训练参数 |
| `attempt/training/training.json` | 查看步骤、实际 token 量和是否更新真实参数 |
| `attempt/validation/round_feedback.json` | 查看两路差值、逐条与技能统计 |
| `attempt/validation/validation_report.md` | 查看单次验证摘要 |
| `benchmark/benchmark_report.json` | 查看独立最终测试，不用于验收 |

`fit.per_record[].whole_record` 是整条差值。`fit.per_record[].by_skill` 是逐条技能片段差值。`fit.by_skill` 是按 token 汇总的技能差值。`execution.before/after` 分别包含总体、任务组、技能和组内技能分母。没有技能证据时，均值和差值为 null。

这里的“整条”只覆盖本次冻结训练数据中实际计入 SFT loss 的位置。它不包含未监督的用户、工具和模板 token。技能片段从同一次前向结果中按证据位置映射，不额外执行模型前向。

## 2. 分步编译与选择

以下配置全部为合成 smoke 示例。预算不构成正式实验协议。

```text
python -m rsi compile-training-data --sources examples/training_validation/sources.jsonl --config configs/training_validation.smoke.contract.json --metadata examples/training_validation/metadata.jsonl --ontology examples/training_validation/ontology.json --policy examples/training_validation/policy.json --model-location configs/training_validation.mock.model.json --output runs/training-compiled --mode mock --device cpu --max-length 512 --data-kind synthetic --message-evidence examples/training_validation/message_evidence.json

python -m rsi select-with-policy --config runs/training-compiled/config.json --data runs/training-compiled/trajectories.jsonl --labels runs/training-compiled/labels.jsonl --ontology runs/training-compiled/ontology.json --policy runs/training-compiled/policy.json --batch-history runs/training-compiled/batch_history.json --allow-synthetic-labels --output runs/training-selection
```

编译输出拒绝覆盖。真实模式将 `--mode` 改为 `hf_local`，并提供经过核验的真实模型定位。静态标签可来自人工、数据集或代码规则。本阶段不实现真实标签生成。

## 3. 准备冻结训练

在 PowerShell 读取第一阶段清单身份：

```powershell
$selectionId = (Get-Content -Raw -Encoding UTF8 runs/training-selection/manifest.json | ConvertFrom-Json).content_id
python -m rsi prepare-training --bundle runs/training-compiled --selection runs/training-selection --selection-id $selectionId --model-location configs/training_validation.mock.model.json --settings configs/training_validation.smoke.json --output runs/training-attempt --run-id local_single --attempt-id attempt_001
```

此步骤复制并核验输入快照，保存 plan.json，登记单批计划。它不重新评分、排序或选数。相同准备请求可以重入。内容冲突必须使用新 attempt 目录。

## 4. 训练前拟合、训练与恢复

```text
python -m rsi evaluate-fit --attempt runs/training-attempt --model parent --device cpu --output runs/training-attempt/validation/fit-parent
python -m rsi train-attempt --attempt runs/training-attempt --device cpu --stop-after-step 1
```

第二条命令返回 `status=PAUSED`，并输出 checkpoint.path 和 checkpoint.sha256。暂停只发生在完整训练步骤后。将这两个实际值用于恢复：

```powershell
$checkpointPath = '填写刚才返回的 checkpoint.path'
$checkpointHash = '填写刚才返回的 checkpoint.sha256'
python -m rsi resume-training --attempt runs/training-attempt --device cpu --checkpoint $checkpointPath --checkpoint-sha256 $checkpointHash
```

不需要恢复验证时，直接运行不带 `--stop-after-step` 的 train-attempt。已完成请求重入会校验并返回已有结果。未完成请求必须明确恢复，不能直接重跑。

新尝试从父 adapter 参数开始，但使用新优化器。恢复同一次尝试则使用原优化器、调度器和随机状态。旧源码或不同依赖不能恢复当前源码的检查点。

## 5. 独立执行与双路验证

```text
python -m rsi evaluate-execution --attempt runs/training-attempt --model parent --device cpu --tasks examples/training_validation/feedback_tasks.json --call-budget 2 --output runs/training-attempt/validation/execution-parent

python -m rsi validate-training --attempt runs/training-attempt --device cpu --tasks examples/training_validation/feedback_tasks.json --call-budget 2
```

validate-training 复用匹配的完整父阶段，再完成缺少的候选阶段。候选单独测量可使用 `evaluate-fit --model candidate` 和 `evaluate-execution --model candidate`。

完成目录必须保持文件清单完整。额外日志请放在目录之外。仅摘要报告或最终清单发布失败时，可以重入 validate-training 来补齐发布；程序先核验完整阶段，不重复测量。未知调用、部分写坏的文件或内容冲突仍会拒绝重入。

没有 `--rule` 时，机械验收为 NOT_RUN。显式规则使用现有 acceptance-1 格式。部分失败时，即使提供规则也不验收。实际服务器 Python 任务必须附加 `--sandbox-config configs/sandbox.json` 并通过 Linux 隔离预检。Windows mock 使用受限表达式解释器。

任务失败可以构成完整测量。基础设施错误和预算不足构成 PARTIAL。PARTIAL 保留完整任务分母，但不发布 attempt 的完整验证清单。评估失败不支持逐任务恢复；不要删除失败目录再重跑相同调用。

## 6. 独立最终测试

以下命令评估父模型。评估候选时，使用演示输出的 candidate_location.json，或根据候选 ArtifactRef 创建经过核验的定位文件。

```text
python -m rsi evaluate-benchmark --bundle runs/training-compiled --model-location configs/training_validation.mock.model.json --mode mock --device cpu --tasks examples/training_validation/final_tasks.json --feedback-tasks examples/training_validation/feedback_tasks.json --call-budget 2 --output runs/training-final
```

该命令不需要 comparison 或训练 attempt。`--feedback-tasks` 只用于已知隔离检查。最终结果只进入 BenchmarkReport，不产生 accept/reject，不进入 RoundFeedback。

## 7. 真实本地小模型与服务器

真实模式需要已有的 torch、transformers、peft、tokenizers 和 safetensors。请在隔离环境中使用可复现版本。程序不安装依赖。可选测试从配置构造极小随机模型和字符 tokenizer；它不下载模型。

先根据本机模型内容生成 ModelRef，再创建 model-location-v1。ModelRef 的基座身份来自 `artifacts.model_manifest`，tokenizer 与模板身份来自 `model_inputs.bound_model`。父 adapter 必须提供真实 manifest 与 SHA-256。不要沿用 mock 模型引用。

```text
python -m rsi training-validation-demo --output runs/tiny-local-validation --mode hf_local --model-location YOUR_LOCAL_LOCATION.json --device cpu
```

只有本机可用模型和 fp32 CPU 配置才能执行此示例。真实模式仍使用合成 smoke 数据。随机 tiny 模型的任务失败属于预期可能结果；不能把它当作模型能力实验。

服务器先读 [训练端交接](训练验证服务器交接.md)。`configs/training_server.template.json` 明确 `executable=false`，它是待核验清单。27B 架构、GPU UUID、数据协议和正式预算均未代填。

## 8. 运行数据留在本地

输出、数据库、检查点和权重保存在 runs。沿用原 `.gitignore`。提交前运行 `git status --short` 与 `git diff --cached --stat`，确认没有私有数据、权重或 runs。不要强制添加被忽略的产物。
