# 功能说明与训练协作交接

公开仓库说明：机器地址、服务器账号和设备 UUID 使用占位值。路径需按目标机器填写。历史结果数字保持不变。

本文对应代码 0.6.0。本文供项目负责人和训练执行者共同使用。

## 1. 当前系统可以完成什么

系统可以比较两种训练数据选择方式。

例如，先准备一个包含编程题目和参考答案的候选池。程序从同一个原始模型开始。一组随机选择数据，另一组按固定评分规则选择数据。两组分别训练一个候选模型。最后，程序让原始模型和两个候选模型回答同一组独立题目。

两组训练使用相同数量的有效监督 token。token 是模型处理的文本单位。有效监督 token 是实际参与训练损失计算的部分。两组可以选择不同数量的完整样本。程序不截断代码来凑齐训练量。

| 功能 | 当前实现 |
| --- | --- |
| 导入数据 | 已支持固定版本的 MBPP Python 编程数据。保留来源、版本和文件校验值。其他数据集需要适配来源格式。 |
| 检查数据 | 检查参考答案能否通过原测试。检查重复样本。保留训练、参考、诊断和反馈任务的使用边界。 |
| 转换训练输入 | 使用实际分词器生成 token 和训练掩码。训练掩码指定哪些位置参与损失。超长输入会明确报错。 |
| 计算评分 | 计算参考答案的平均预测误差，以及模型预测的分散程度。程序使用固定参考组换算相对位置。 |
| 选择数据 | 支持随机排名和固定规则排名。两者共用完整样本组批、预算检查和覆盖要求。 |
| 训练模型 | 支持单卡 LoRA 监督微调。LoRA 只更新新增的少量参数。两个分支分别从同一原始基座开始。 |
| 记录诊断 | 记录训练损失，以及固定诊断数据在训练前后的交叉熵。可额外标记 Python 控制关键字和 return 关键字。 |
| 执行评估 | 在 Linux 隔离环境中执行模型生成的 Python 代码。限制网络、文件写入、新进程、时间、内存和输出。 |
| 保存与恢复 | 保存输入版本、所选样本、实际成本和模型产物。支持从完整训练步骤的检查点恢复。 |
| 生成报告 | 分别报告训练分支相对原始模型的变化，以及固定选择相对随机选择的差值。 |

交叉熵描述模型对给定参考目标的预测误差。交叉熵下降不能单独证明模型更会解题。关键字诊断也只表示这些语法位置的预测情况，不能直接当作完整能力标签。

## 2. 当前完成边界

当前系统是单轮受控比较工具。固定策略由配置给出。

以下功能尚未实现：Agent 根据反馈自动修改策略、跨轮经验学习、候选自动晋级、探针驱动的按需评分，以及多卡训练。

当前训练后端只支持单卡、每次一条样本、无梯度累积的 LoRA。它固定更新 q_proj 和 v_proj 两类模块。目标 27B 模型的架构和模块名称需要先核对。

8×H200 是计划使用的设备。当前代码没有完成八卡训练适配。`configs/h200_8gpu.draft.json` 是草稿，不能作为可直接运行的八卡配置。

## 3. 已经执行过的检查

已有验证记录显示，Linux 服务器的 160 项自动测试全部通过。本地 Windows 通过 148 项，跳过 12 项。本文没有重新运行这些训练和测试。

已有实际运行使用 Qwen2.5-0.5B-Instruct 和单张 RTX 5880。程序完成了真实数据评分、两组训练、暂停恢复和 96 次生成评估。两组各训练了 512 个监督 token。

该运行验证了工程流程。该运行没有建立固定选择优于随机选择的证据。512 token 是工程检查值，不能直接作为目标模型的研究训练预算。

该运行出现较多格式错误。目标模型实验需要先在独立开发题目上检查提示模板、代码格式和生成长度，再固定评估规则。

## 4. 首轮实验要回答什么

首轮实验检查：在同一个模型、同一个候选池和相同监督量下，固定选择是否比合格随机选择带来更多任务收益。

| 分支 | 执行操作 | 比较用途 |
| --- | --- | --- |
| 原始模型 | 不训练，直接评估 | 提供起点 |
| 随机选择分支 | 随机选择合格数据，再训练 | 测量普通监督微调带来的收益 |
| 固定选择分支 | 按冻结规则选择数据，再训练 | 相对随机组估计数据选择的额外作用 |

两个训练分支均从同一个原始模型开始。固定组不能接着随机组的训练结果继续训练。

两组监督 token 总量相同。程序还会记录上下文总量、更新次数和耗时。相同监督量不表示相同计算成本。

这项实验不能直接证明“模型经过多轮反馈后，筛选能力越来越好”。后续仍需要接入相应机制，并开展独立的筛选能力评估。

## 5. 负责人和执行者分别负责什么

| 工作 | 负责方 | 应交付的信息 |
| --- | --- | --- |
| 确定研究条件 | 项目负责人 | 模型、数据角色、主指标、训练预算、种子列表、停止规则 |
| 检查目标环境 | 训练执行者 | 模型本地目录、模型配置、GPU 信息、软件版本、隔离检查结果 |
| 适配当前缺失功能 | 框架开发者 | 对目标模型的适配；如确需多卡，则实现和验证多卡后端 |
| 执行冻结的实验 | 训练执行者 | 按确认配置运行，保存所有成功与失败尝试 |
| 分析结果 | 项目负责人和框架开发者 | 比较任务收益、保持变化、数据差异和实际成本 |

训练执行者不需要自行决定论文主张，也不需要自行选择表现最好的配置或种子。

第一步先收集目标环境信息。此时不用启动 27B 训练，也不用下载模型到个人电脑。

请填写以下表格。

| 项目 | 执行者填写 |
| --- | --- |
| 27B 模型完整名称 | 待填写 |
| 模型属于基座版还是指令版 | 待填写 |
| 模型在训练服务器上的完整目录 | 待填写 |
| 模型 config.json | 回传文件内容 |
| GPU 型号、完整 UUID 和可用显存 | 回传设备查询结果 |
| Python 与模型库版本 | 回传版本查询结果 |
| 可用磁盘空间 | 待填写 |
| Linux 隔离检查是否通过 | 回传检查日志 |

以下命令在 Linux 训练服务器执行。先把路径替换为实际值。不要保留示例路径。

```bash
export RSI_CODE=/absolute/path/to/framework
export RSI_PY=/absolute/path/to/python
export RSI_MODEL=/absolute/path/to/local/model
cd "$RSI_CODE"
nvidia-smi --query-gpu=index,uuid,name,memory.used,memory.total --format=csv
"$RSI_PY" --version
"$RSI_PY" -m pip show torch transformers peft accelerate safetensors
cat "$RSI_MODEL/config.json"
df -h "$RSI_CODE" "$RSI_MODEL"
```

模型配置先用于检查架构、分词器、模板和目标模块。程序当前使用本地 safetensors 权重，不启用远程自定义代码。目标模型是否兼容需要实际核对。

## 7. 目标环境通过后怎样训练

### 第一步：复现软件和隔离检查

从交付源码包建立独立目录。使用专用 Python 环境。已验证的模型依赖版本保存在 pyproject.toml 的 hf 部分。隔离执行还需要系统的 Bubblewrap、libseccomp 和 /usr/bin/python3。

```bash
cd "$RSI_CODE"
export OMP_NUM_THREADS=1
export PYTHONPATH=.
mkdir -p runs
RSI_RUN_SANDBOX_TESTS=1 CUDA_VISIBLE_DEVICES='' \
  "$RSI_PY" -m unittest discover -s tests -v
CUDA_VISIBLE_DEVICES='' "$RSI_PY" -m rsi sandbox-check \
  --config configs/sandbox.json --output runs/handoff-sandbox-001.json
```

隔离检查输出应为 VERIFIED。输出文件必须尚不存在。检查失败时保留日志，并回传失败信息。

### 第二步：确认目标模型能执行

先使用少量数据检查分词、评分、一次更新、保存和重新加载。再检查独立开发题目的输出格式与生成长度。

模型能否在单卡运行，需要实际测量。若当前单卡后端无法满足条件，回传显存峰值和错误日志，由框架开发者处理。不要把 world_size 改为 8 后继续运行。

### 第三步：固定正式开发配置

项目负责人确认候选池、参考组、固定诊断和独立反馈题目。项目负责人再确认每组训练量、学习率、LoRA 配置、生成长度、指标和种子列表。

当前 MBPP 目标组和保持组是工程划分。研究任务定义需要另行确认。最终测试集继续隔离。

执行者使用新配置文件保存这些值。默认学习率 0.0001、LoRA 秩 4、上下文长度 1024 和训练量 512 token 都来自小模型工程检查。不能把它们直接当作 27B 的已验证参数。

### 第四步：运行三组比较

操作顺序如下。

1. 导入固定版本数据，并检查参考答案。
2. 使用目标模型的分词器编译数据。
3. 检查配置、数据和预算。
4. 评分并生成随机组与固定组批次。
5. 从同一原始模型分别训练两个分支。
6. 对原始模型和两个候选执行相同任务评估。
7. 生成对照报告。

命令依次为 import-mbpp、compile-data、check-comparison、run-comparison、evaluate-pilot 和 report-comparison。暂停后的恢复命令为 resume-comparison。

完整参数见 [运行手册](真实数据训练对照运行手册.md)。该手册中的 /data/TRAINING_USER 路径属于现有验证服务器。换到新服务器时，必须改为实际路径。GPU UUID 和 expected_device_name 也必须使用目标服务器的实际值。

源码包不包含原始 MBPP 文件。可单独传递已固定版本的原始文件，也可按 configs/mbpp.source.json 中的固定 URL 获取。导入程序会检查文件哈希。

### 第五步：运行多个配对种子

先完成单次完整流程，再执行预先确认的种子列表。每个种子使用独立配置和新目录。所有种子使用相同候选池、任务集和训练配置。

不要只回传表现最好的种子。不要把同一任务在多个种子下的结果当作全部独立的新题目。

## 8. 执行者需要回传什么

训练执行者应回传整个运行的非权重产物。不要只回传一张分数表。

| 材料 | 用途 |
| --- | --- |
| 实际使用的配置和环境记录 | 核对模型、设备、软件、预算与种子 |
| 数据导入和编译报告 | 核对来源、划分、拒绝条目和监督量 |
| 两组数据清单 | 核对选择是否不同，以及重合程度 |
| 训练日志与状态库 | 核对更新、恢复、失败和实际成本 |
| 原始生成与逐题执行结果 | 区分格式失败、运行失败和答案错误 |
| 固定诊断结果 | 检查参考目标和关键片段的预测变化 |
| summary/report.md 与 summary/summary.json | 查看最终对照结果 |

模型权重、检查点张量和优化器状态保留在服务器，并提供完整路径。若发生失败，保留原目录和日志。不要删掉失败记录后用同一名称重跑。

## 9. 可以直接转发的任务说明

请协助执行 RSI 数据筛选项目的首轮开发实验。当前代码版本为 0.6.0。

请先回传目标 27B 模型的完整名称、本地目录、config.json、GPU 信息和软件版本。当前框架只实现了单卡 LoRA，八卡训练尚未接入。我们会先确认目标模型兼容性和显存需求，再确定执行方式。

首轮实验包含原始模型、随机选数训练和固定规则选数训练三组。两个训练分支从同一原始模型开始，并使用相同监督 token 总量。三组执行同一批独立题目。实验重点是固定选择相对随机选择的差值。

请先完成环境检查和小规模完整流程。确认后，按约定的数据、预算和种子列表运行。请保留全部成功和失败记录，并回传配置、数据清单、状态库、逐题结果和汇总报告。模型权重和检查点保留在服务器。

具体运行步骤见随附手册。手册中的旧服务器路径需要替换。默认 512 token 训练量用于工程检查，不是 27B 的正式实验参数。
