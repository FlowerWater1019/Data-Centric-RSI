# 第一阶段运行手册

本手册说明基础命令。0.3.0 的真实模型流程见 [小模型工程验证运行手册](小模型工程验证运行手册.md)。0.4.0 的新增流程见 [恢复与任务评估运行手册](恢复与任务评估运行手册.md)。下文“未接入”描述的是第一阶段的原范围；当前能力以新手册为准。

## 1. 本手册的范围

本手册帮助你检查框架，并生成随机选择与固定策略的对照计划。

当前流程只使用 CPU。你现在不需要启动 H200 训练任务。程序不会执行 SFT，不会生成候选模型，也不会计算任务成功率。

文中的轨迹、评分和 token 预算均为演示值。它们只用于检查程序。

## 2. 准备运行目录

本地工程位于 `D:\RSI\framework`。在 PowerShell 中进入该目录。

```powershell
Set-Location D:\RSI\framework
```

如需在 Linux 服务器检查框架，先把整个 framework 目录传到服务器。保留 rsi、configs、examples、tests 和 docs 等目录的相对位置。然后进入服务器上的工程根目录。

下面命令中的 `/path/to/RSI/framework` 是占位路径。请替换为实际目录。

```bash
cd /path/to/RSI/framework
```

后续命令都从工程根目录 framework 执行。两种系统都可以使用后续命令中的相对路径。

## 3. 检查 Python

运行以下命令。

```text
python --version
```

要求 Python 3.11 或更高版本。如果服务器只有 python3 命令，请在后续步骤中统一使用 python3。

本阶段只依赖 Python 标准库。无需安装 PyTorch、Transformers 或 PEFT。运行源码也不要求先执行包安装。

## 4. 运行自动测试

执行以下命令。

```text
python -m unittest discover -s tests -v
```

预期结果：命令退出码为 0，最后显示 `OK`。测试数量以当前代码输出为准。

测试会在临时目录创建状态数据库。测试中的预算消耗是人工构造的数据，不是实际 GPU 训练。

测试按模块分文件。测试还会启动独立的 Python 子进程，检查命令流程。当前无需手工逐个运行测试文件。

如果出现 `FAILED`，先保留完整输出。不要把后续计划当作已通过验证的实验输入。

## 5. 校验演示数据

执行以下命令。

```text
python -m rsi validate --config configs/smoke.json --data examples/trajectories.demo.jsonl --require-current-scores
```

预期结果包含以下字段。

```json
{
  "status": "VALIDATED",
  "validation_level": "structural",
  "records": 7,
  "current_score_records": 4,
  "stale_or_missing_score_ids": [],
  "purpose": "smoke",
  "training_status": "NOT_RUN"
}
```

实际输出还包含目标硬件声明。

`structural` 表示程序检查了字段、掩码、角色隔离和版本引用。它不表示程序执行了轨迹代码，也不表示程序重新计算了 NLL 或熵。

`--require-current-scores` 要求当前可选数据具有相容分数。没有该参数时，校验命令会报告旧分数，但不因旧分数单独失败。固定策略在生成计划时仍拒绝缺失或过期分数。

## 6. 创建冻结的运行记录

执行以下命令。

```text
python -m rsi init --config configs/smoke.json --data examples/trajectories.demo.jsonl --db runs/stage1.sqlite3 --run-id smoke-001 --mode controlled
```

首次执行时，预期输出 `created: true`。程序创建 SQLite 数据库，并把配置和数据快照写入同一事务。

使用相同输入重复执行时，预期输出 `created: false`。程序不会新建重复运行，也不会清空旧记录。

如果你修改了配置或数据，请使用新的 run-id。例如，把 `smoke-001` 改为 `smoke-002`。同一 run-id 不能绑定不同输入。

后续计划读取数据库中的冻结快照。修改原始文件不会改变已有运行。

## 7. 生成随机与固定策略对照计划

执行以下命令。

```text
python -m rsi plan-comparison --db runs/stage1.sqlite3 --run-id smoke-001 --comparison-id pair-001
```

预期输出包含 random 和 fixed 两个分支。两个分支共享模型起点、输入快照、随机种子、监督预算及训练配置。

当前演示中，每个分支选择两条轨迹，计划监督量为 8 个演示 token。固定策略选择 c 和 b。你应以实际计划输出检查随机分支。

检查以下字段。

| 字段 | 预期含义 |
| --- | --- |
| context_id | 两个分支来自同一评估情境 |
| supervised_tokens | 两个分支的计划有效监督量相同 |
| context_tokens | 计划输入长度；当前示例相同，正式数据可能不同 |
| fingerprint | 批次内容标识，与记录排列顺序无关 |
| same_batch | 两个方法是否恰好选择了相同批次 |
| training_status | 必须为 NOT_RUN |
| metrics | 必须为 null |

如果 same_batch 为 true，这次计划不能区分两种选择方法。程序会保留该事实，不会强行替换样本来制造差异。

再次执行相同命令时，程序返回已保存的计划。它不会重新抽样，也不会追加重复计划事件。

计划不预留真实训练资源，不产生计算消耗。未来调度后端提交作业时，才调用预算预留接口。

## 8. 查看状态

执行以下命令。

```text
python -m rsi status --db runs/stage1.sqlite3 --run-id smoke-001
```

预期运行状态为 planned，训练状态为 NOT_RUN。各项预算的 used 和 reserved 均为 0。

planned 只表示计划已经保存。它不表示模型完成训练。

关闭终端后，可以重新执行同一命令。状态从数据库读取，不依赖原进程仍在运行。

status 和 export 使用只读数据库连接。它们不会创建新数据库或修改已有运行记录。

## 9. 导出状态报告

执行以下命令。

```text
python -m rsi export --db runs/stage1.sqlite3 --run-id smoke-001 --output runs/smoke-001-report.json
```

程序输出报告路径。报告包含事件、计划、预算和目标硬件。

导出文件只用于查看与审计。修改导出文件不会改变数据库状态。

如果目标文件已经存在，程序拒绝覆盖。你可以指定新的文件名，例如 `runs/smoke-001-report-2.json`。

## 10. H200 配置的使用边界

`configs/h200_8gpu.draft.json` 记录以下目标。

| 项目 | 当前记录 |
| --- | --- |
| GPU | H200 |
| 数量 | 8 |
| 每张显存 | 用户提供的 144 GB |
| 信息来源 | user_reported，尚未探测实际设备 |
| 目标训练进程数 | 8 |
| 候选精度 | bf16，仍需目标模型与运行环境验证 |
| LoRA 秩、学习率、序列长度和批量参数 | null，待配置 |
| 模型、分词器及评分版本 | TO_CONFIGURE，待配置 |

该文件中的筛选预算、配额、评分预算和评估次数都是模板演示值。它们不是根据 H200 测量得到的最优设置，也不是已批准的正式实验预算。

不要把该草稿与合成演示数据直接组合成正式实验。演示数据使用合成分词，程序会拒绝将其用于 draft 或 research 配置。

8 张卡的显存不能被当作单张连续显存使用。训练并行方式、模型规模和有效批量需要在接入真实后端后确定。本阶段不提供可执行的分布式训练启动命令。

## 11. 当前不能运行的操作

`python -m rsi train` 是保留入口。执行它会返回退出码 2，并明确说明真实训练后端尚未实现。

当前不支持真实模型分词导入、前向评分、LoRA 更新、任务执行、统计验收或模型晋级。不能通过修改状态文本把这些工作标记为完成。

后续真实训练接入后，运行手册会另行补充模型准备、设备检查、启动、恢复和结果验收步骤。现在无需运行 GPU 实验。

## 12. 常见错误

| 提示 | 原因 | 处理方法 |
| --- | --- | --- |
| 存在未知字段 | 配置字段拼写错误，或使用了未支持字段 | 根据接口说明核对配置 |
| 文本内容与 SHA256 不一致 | 文本修改后未同步数据记录 | 重新生成并验证完整数据版本 |
| 正向监督只能覆盖有效 assistant token | 掩码包含工具、用户、错误或未知动作 | 按证据修正掩码；不要直接改正确性标签绕过检查 |
| 数据角色存在泄漏 | 同一分组或内容出现在不允许共用的角色 | 修正数据划分和分组标识 |
| 分数版本过期或不相容 | 模型、轨迹、掩码、参考组或 CDF 版本不一致 | 使用真实评分后端生成新分数；本阶段只能检查输入 |
| 贪心组批未找到合法批次 | 当前排序下无法满足预算或配额 | 检查数据覆盖与预算；该提示不证明约束无解 |
| 两组实际计划监督量不同 | 可变长度数据未形成等监督量对照 | 修订事先声明的组批设计并创建新运行 |
| 已有运行的输入不同 | 复用了旧 run-id | 使用新的 run-id |
| 目标报告已存在 | 导出操作不覆盖文件 | 指定新的报告文件名 |
| 数据库版本不支持或结构不完整 | 文件版本不匹配，或表结构缺失 | 保留原文件。使用匹配版本的程序检查；不要手工补表 |
| 文件必须使用 UTF-8 编码 | 配置或数据文件编码错误 | 将输入另存为 UTF-8，再重新校验 |

不要直接编辑 SQLite 表来修复实验。保留旧运行，修正输入后创建新运行。
