# 真实数据与隔离执行运行手册

公开仓库说明：机器地址、服务器账号和设备 UUID 使用占位值。路径需按目标机器填写。历史结果数字保持不变。

本文对应 0.5.0。当前命令检查真实数据入口与 Python 隔离执行。它们不运行真实数据训练，也不运行官方最终测试集。

## 1. 本地检查

1. 在 PowerShell 中进入代码目录。

   ```powershell
   Set-Location D:\RSI\framework
   ```

2. 运行基础测试。

   ```text
   python -m unittest discover -s tests -v
   ```

   本地缺少模型依赖时，三个模型测试会跳过。八个 Linux 隔离集成测试默认跳过。跳过不代表通过。

## 2. 服务器环境

以下命令在已授权的 Linux 服务器执行。服务器已部署当前代码。

1. 进入工程目录。

   ```bash
   cd /data/TRAINING_USER/rsi-framework/20261018-v0.5.0
   ```

2. 指定已有 Python 环境。

   ```bash
   export RSI_PYTHON=/data/TRAINING_USER/opd-if-research/.venv/bin/python
   ```

3. 指定已有小模型。

   ```bash
   export RSI_MODEL=/data/TRAINING_USER/.cache/modelscope/hub/models/Qwen/Qwen2.5-0.5B-Instruct
   ```

4. 检查隔离机制。

   ```bash
   "$RSI_PYTHON" -m rsi sandbox-check \
     --config configs/sandbox.json \
     --output runs/manual-sandbox-check-01.json
   ```

   输出路径必须尚不存在。预期状态为 `VERIFIED`。该步骤不加载模型，不调用 GPU。

5. 运行包含隔离测试的完整测试集。

   ```bash
   RSI_RUN_SANDBOX_TESTS=1 CUDA_VISIBLE_DEVICES='' OMP_NUM_THREADS=1 \
     "$RSI_PYTHON" -m unittest discover -s tests -v
   ```

   该命令检查超时、输出上限、内存上限和其他隔离行为。没有 bwrap、libseccomp 或系统 Python 时，测试会明确失败。不要关闭隔离保护来绕过失败。

## 3. 准备原始数据

服务器已有本次固定版本的数据：`runs/mbpp-upstream/mbpp-mbpp.jsonl`。使用该文件时，无需再次下载。

在新服务器上，可先创建一个新的下载目录，再下载固定文件：

```bash
mkdir runs/mbpp-download-01
curl --fail --location \
  https://raw.githubusercontent.com/google-research/google-research/f82046ba5aabbbb427dbfd38a254d26bff08b533/mbpp/mbpp.jsonl \
  --output runs/mbpp-download-01/mbpp.jsonl
```

导入程序会核对 `configs/mbpp.source.json` 中的 SHA256。下载文件不匹配时，不要修改哈希来让校验通过。先确认来源与版本。

## 4. 导入工程子集

1. 设置新的导入目录。

   ```bash
   export RSI_BUNDLE=runs/manual-mbpp-import-01
   ```

2. 导入数据，并检查参考解。

   ```bash
   "$RSI_PYTHON" -m rsi import-mbpp \
     --source runs/mbpp-upstream/mbpp-mbpp.jsonl \
     --origin configs/mbpp.source.json \
     --sandbox-config configs/sandbox.json \
     --output "$RSI_BUNDLE" \
     --limit-per-role 4 \
     > runs/manual-mbpp-import-01.receipt.json
   ```

   `--limit-per-role 4` 对五种工程角色分别取最多四条。程序先冻结编号，再测试参考解。命令保留原始数据，不覆盖旧运行。

3. 查看导入结果。

   ```bash
   cat runs/manual-mbpp-import-01.receipt.json
   ```

   成功状态为 `IMPORTED`。输出包含清单哈希、训练侧来源数、反馈任务数、拒绝数和测试调用数。格式警告写入标准错误，不会混入上述 JSON 收据。

4. 检查被排除或拒绝的条目。

   ```bash
   cat "$RSI_BUNDLE/rejected.json"
   ```

   角色划分和未选中原因保存在 `selection.json`。参考解测试保存在 `reference_checks` 和 `calls`。不要删除失败记录后补选样本。

## 5. 编译为现有轨迹格式

1. 从原始导入收据读取清单哈希。

   ```bash
   export RSI_BUNDLE_SHA256=$("$RSI_PYTHON" -c 'import json; print(json.load(open("runs/manual-mbpp-import-01.receipt.json"))["manifest"]["sha256"])')
   ```

2. 设置新的编译目录。

   ```bash
   export RSI_COMPILED=runs/manual-mbpp-compiled-01
   ```

3. 使用本地 tokenizer 编译数据。

   ```bash
   CUDA_VISIBLE_DEVICES='' HF_HUB_OFFLINE=1 TRANSFORMERS_OFFLINE=1 \
     "$RSI_PYTHON" -m rsi compile-data \
     --bundle "$RSI_BUNDLE" \
     --bundle-sha256 "$RSI_BUNDLE_SHA256" \
     --config configs/mbpp.engineering.json \
     --model-path "$RSI_MODEL" \
     --output "$RSI_COMPILED" \
     --max-length 1024
   ```

   该步骤不加载模型权重到 GPU。报告应写明 `scores=NOT_COMPUTED` 和 `training=NOT_RUN`。轨迹超长时，程序会报错，不会自动截断。

4. 写入现有状态接口。

   ```bash
   "$RSI_PYTHON" -m rsi init \
     --config "$RSI_COMPILED/contract.json" \
     --data "$RSI_COMPILED/trajectories.jsonl" \
     --db runs/manual-mbpp-state-01.sqlite3 \
     --run-id mbpp-import-check
   ```

   预期 `training_status` 为 `NOT_RUN`。该命令只冻结输入，不执行训练。

## 6. 检查模型代码的隔离评估

本次可以复用 0.4.0 已完成的模型产物。它们曾在合成轨迹上训练。本步骤只检查评估接口，不能比较真实数据训练效果。

1. 查看目标 GPU 占用。

   ```bash
   nvidia-smi --query-gpu=uuid,name,memory.used,utilization.gpu --format=csv
   ```

2. 在设备可用时绑定完整 UUID。

   ```bash
   export CUDA_VISIBLE_DEVICES=GPU-REPLACE_WITH_FIRST_DEVICE_UUID
   ```

3. 设置离线运行参数。

   ```bash
   export HF_HUB_OFFLINE=1 TRANSFORMERS_OFFLINE=1 TOKENIZERS_PARALLELISM=false OMP_NUM_THREADS=4
   ```

4. 执行三组评估。

   ```bash
   "$RSI_PYTHON" -m rsi evaluate-pilot \
     --pilot /data/TRAINING_USER/rsi-framework/20261018-v0.4.0/runs/resumed \
     --tasks "$RSI_BUNDLE/feedback_tasks.json" \
     --rule configs/acceptance.engineering.json \
     --model-path "$RSI_MODEL" \
     --output runs/manual-isolated-evaluation-01 \
     --device cuda:0 \
     --sandbox-config configs/sandbox.json \
     --max-context-length 1024
   ```

5. 查看报告。

   ```bash
   cat runs/manual-isolated-evaluation-01/report.json
   ```

   预期 `task_execution=COMPLETED`，`executor=bubblewrap_seccomp_v1`。八道任务对应三个模型，共 24 次生成尝试。每组只有四道任务，因此工程验收应为 `inconclusive`。`model_promotion` 应为 `NOT_APPLIED`。

6. 查看逐任务执行证据。

   ```bash
   cat runs/manual-isolated-evaluation-01/baseline/evaluation.json
   ```

   格式错误会导致该任务不启动测试，但仍计为任务失败。已经启动的测试保存独立的开始记录和结果记录。隔离启动失败会终止整个评估，并保存失败原因。

## 7. 后续运行边界

现在不要把真实数据直接替换进原 `pilot` 命令。该命令仍使用等长合成候选。下一阶段会接入真实评分、变长组批和等监督预算训练对照。

当前不需要运行 27B 或八卡实验。框架完成上述接口后，再冻结真实研究实验的参数、数据划分和验收规则。
