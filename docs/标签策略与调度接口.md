# 标签、策略与调度接口

## 范围

本接口连接独立标签、筛选策略和预设调度。它不运行 teacher、训练、任务评估或控制模型。所有训练与任务执行状态为 `NOT_RUN`。模拟验收只保存预设结果。

例如，默认演示先按 `code_generation` 偏好选择四条轨迹。调度随后提高 `regression_check` 偏好，并增加最低覆盖要求。第二次选择复用同一批数据与分数。

所有文件使用 UTF-8。解析器拒绝缺字段、未知字段、重复 JSON 键、空 ID、非有限数值、数值位置上的 bool 及越界数值。解析错误包含字段位置。公开对象使用冻结数据类、元组和只读映射。`to_dict()` 返回独立副本。构造器不能替代解析器。

## DataLabels

`data-labels-v1` 使用独立 JSONL。每条 candidate 恰好有一条标签。关联键为 `data_id` 和 `trajectory_version`。参考与探针不需要标签。新选择入口拒绝任何 `final_test` 轨迹，也拒绝缺失、重复、孤儿和过期标签。

| 字段 | 类型与约束 |
| --- | --- |
| schema_version | 固定为 `data-labels-v1` |
| data_id、trajectory_version、label_version | 非空身份字符串 |
| domain | `coding` 或 `general`；必须与技能表及策略一致 |
| provenance | dataset_id、dataset_revision、source_record_id、label_mode、annotation_seed |
| partition | role、split_group、duplicate_group；必须与旧轨迹完全一致 |
| task | task_type、trajectory_type、harness_protocol、language |
| task_ref | task_id 必填；repository、base_commit、environment_id、evaluation_spec_id 可以为 null |
| protocol_ref | harness_id、harness_version 必填；tool_schema_version 可以为 null |
| quality_flags | trajectory_complete、result_verified、protocol_valid、quality_pass、no_answer_leakage；各值仅允许 true、false、null |
| quality_annotation | source、rule_version、evidence_refs |
| skills | ontology_version 和 items；每项包含 skill_id、source、evidence_refs |
| cost | tokenization_version、context_tokens、supervised_tokens、length_bucket |
| model_scores | `missing` 或 `available` 联合类型，见下文 |
| usage | ever_used_in_training_attempt、in_accepted_lineage、training_attempt_ids、cumulative_supervised_tokens |

`label_mode` 仅允许 `synthetic_fixture` 和 `annotated`。前者要求非负整数 annotation_seed。后者允许 seed 为 null。`annotated` 只表示来源类型，不代表标签正确。

source 枚举为 `seeded_random`、`human`、`teacher`、`code`、`dataset`、`synthetic_fixture`。这些值只记录来源，不自动启动对应后端。

`trajectory_type` 允许 `single_turn`、`multi_turn`、`tool_interaction`。其余 task 名称使用非空 ID。task_ref 和 protocol_ref 只声明引用。程序不会据此下载仓库、镜像或执行工具。

技能表使用 `skill-ontology-v1`，包含 ontology_version、domain、skills。每个技能包含 id、name、description。技能 ID 必须唯一。标签技能必须属于该表，不得重复。空技能列表合法。版本必须精确相同，不做静默映射。自定义演示技能列表使用内容派生版本，避免沿用默认技能表身份。

`model_scores={"status":"missing"}` 不允许其他字段。`available` 必须具有 checkpoint_id、trajectory_version、mask_version、scoring_rule_version、reference_version、cdf_version、normalization_group、nll、entropy、nll_percentile、entropy_percentile。NLL 和 entropy 为非负有限数。百分位在 `[0,1]`。目前只支持 `normalization_group=all_candidates`。

partition、skills、cost token 数、usage 和 model_scores 都是旧轨迹快照断言。scoring_rule_version 映射旧 scores.rule_version。其他评分字段精确比较。标签不能覆盖旧技能、分数或使用历史。

`context_tokens` 沿用旧 `record.token_count`，表示总输入长度。它不是非监督 token 数。`supervised_tokens` 来自 loss mask。当前 `cost.tokenization_version` 明确绑定旧轨迹的 tokenizer_revision。这是相对任务文件的字段语义细化。模板版本另由轨迹和合同绑定。

quality_flags 的 null 表示未知。策略可排除未知值或明确报错。旧 `TrajectoryRecord.is_eligible` 始终有效。标签不能放开旧质量失败、accepted lineage 或零监督数据。

模拟标签必须同时满足显式 `--allow-synthetic-labels` 和 `purpose=smoke`。策略 allowed_label_modes 不能单独授予此权限。`selection-demo` 是显式模拟入口，内部仍核对 smoke 配置。

标签中的 evidence_refs 默认为空。纯接口 `parse_labels(..., evidence_ids=frozenset(...))` 接收调用方已解析的证据 ID 注册表。非空引用必须存在于该表。当前 CLI 未接入外部标签证据清单，因此拒绝所有非空标签证据引用。

## SelectionPolicy

`selection-policy-v1` 是完整不可变快照。它不替代 ExperimentContract。

| 字段 | 内容 |
| --- | --- |
| schema_version、policy_id、parent_policy_id | 格式、当前策略和父策略身份；根策略父 ID 为 null |
| domain、skill_ontology_version | 精确绑定领域和技能表 |
| created_by | type、controller_checkpoint_id、dispatch_id；人工根策略后两项为 null；调度应用自动填写来源 |
| eligibility | allowed_label_modes、required_true_flags、unknown_flag_action、allowed_task_types、allowed_trajectory_types、allowed_harness_protocols、allowed_languages、excluded_data_ids、deferred_batch_ids |
| scoring | formula_version、score_requirement、reference_version、cdf_version、nll_preference、entropy_preference、skill_preferences、skill_aggregation、weights |
| batch_constraints | supervised_token_budget、allowed_shortfall、max_context_tokens_per_sample、min_skill_token_shares、min_task_type_token_shares、max_task_type_token_shares、duplicate_rule、allow_within_batch_repetition |
| execution | packing_rule、quota_handling、tie_breaker、seed |
| description | 非空人工说明，不参与数值评分 |

`formula_version=weighted_utility_v1`，`score_requirement=current_checkpoint`，`skill_aggregation=max`。评分复用旧 FixedStrategy、Preference 和 `selection.score_terms`。只有 NLL 效用、entropy 效用和最大技能偏好三项。未配置偏好的合法技能及空技能列表贡献 0。权重非负，总和误差不超过 `1e-9`。

梯形偏好沿用旧公式。support 为 `[a,d]`，preferred 为 `[b,c]`，要求 `a<b<=c<d`。区间外效用为 0，偏好区间内为 1，两侧线性变化。程序不按过滤后的子集重新计算百分位。

筛选顺序为旧基础资格、新标签资格、长度检查、当前评分核验、排名、共用组批、配额检查。即使数值评分权重为 0，合格候选仍必须具有当前分数。

allowed_task_types 同时构成本策略的任务类型注册表。任务比例映射只能引用其中的键。技能比例映射只能引用技能表中的键。每项比例在 `[0,1]`。任务最低比例总和不得超过 1，同类型最低比例不得超过最高比例。技能可重叠，其比例总和可超过 1。

目前支持 `greedy_v1` 和 `exact_ranked_v1`。精确组批要求 allowed_shortfall 为 0，沿用旧规模上限与重复池拒绝规则。`quota_handling=postcheck_fail`，`tie_breaker=data_id_ascending`，`duplicate_rule=one_per_duplicate_group`，禁止批内重复。不截断轨迹、不重复采样、不重排以补配额。

`adapt_policy` 返回独立派生合同，不修改原合同或输入。策略预算不能超过原单批预算和总训练预算。参考组与 CDF 版本必须匹配原合同。派生合同 ID 为原 ID 加冒号和策略 ID。报告分别保存原合同和派生合同哈希。策略 seed 控制新入口，旧入口 seed 语义保持。

## 历史与选择报告

`batch-history-v1` 包含 batches。每条记录包含 batch_id、policy_hash、labels_hash、dataset_hash、member_ids。deferred_batch_ids 必须解析到这些记录。暂缓没有 TTL，只有后续补丁 remove 才能释放。历史清单是调用方冻结的输入声明，不是对外部历史真实性的自动证明。

`selection-report-v1` 包含状态、模式、NOT_RUN 标记、各输入哈希、派生合同、每条候选解释、阶段计数和批次。上下文身份包含合同、派生合同、模型、数据、标签、技能表、策略、评分与历史。改变标签、策略或历史会改变 context_id。批次 fingerprint 仍只标识原成员内容与使用次数，成员不变时可保持相同。

候选解释包括资格、所有可用排除原因、是否评分、原始分数与百分位、效用、最大技能匹配、三项加权值、总分、ranking_position、selected_position。排除样本的分数与排名为 null。没有逐步组批原因追踪时，只记录 `not_selected_by_packing`。

输入和评分错误抛出 ValidationError。预算失败报告状态为 `BUDGET_FAILED`。配额失败为 `QUOTA_FAILED`。失败报告不包含可执行批次。CLI 在这两种失败下返回非零且不发布输出目录。纯函数调用方仍可读取完整失败报告。

## FeedbackFixture

`feedback-fixture-v1` 只接收合成反馈。

| 字段 | 内容 |
| --- | --- |
| feedback_id、round_id、batch_id | 当前反馈、轮次和批次身份 |
| parent_checkpoint_id、candidate_checkpoint_id | 父模型与假定候选模型身份；不会加载模型 |
| source、data_role | 固定为 synthetic_fixture、feedback |
| fit | scope=selected_training_batch、supervised_tokens、before/after 的 nll/entropy |
| execution | target、retention、by_skill；每项为 task_count、before_passed、after_passed |
| acceptance | status、source=fixture、rule_version=fixture-v1、reason |
| evidence | ID 到 `{kind, skill_id}` 的严格注册表 |

通过数不能超过任务数。成功率由 `ExecutionCounts.rates()` 计算，不接收冗余输入均值。task_count 为 0 时返回 MISSING 和 null。技能分组可以重叠，不求和推算总体任务量。

证据 kind 允许 fit_nll、fit_entropy、target_execution、retention_execution、skill_execution、acceptance_result。仅 skill_execution 需要非空 skill_id，且必须存在于 by_skill。其他类型的 skill_id 必须为 null。证据不能指向任意表达式或 final_test。

acceptance.status 为 accepted、rejected 或 inconclusive。它是预设 fixture 结果，不调用正式验收算法。生成器同时输出 rejected 和 inconclusive 示例。

## DispatchDecision

| 字段 | 内容 |
| --- | --- |
| schema_version、dispatch_id、round_id | 固定格式 dispatch-decision-v1 及本次身份 |
| controller | type、checkpoint_id、prompt_version；本阶段仅应用 fixture |
| inputs | parent_checkpoint_id、candidate_checkpoint_id、current_policy_id、batch_id、feedback_id、history_dispatch_ids |
| diagnosis | summary、observations、hypotheses、limitations |
| model_action | recommendation、reason、acceptance_evidence_ref |
| natural_language_dispatch | 非空说明，只保存、不执行 |
| policy_update | base_policy_id、proposed_policy_id、set、add、remove |
| next_action | select_next_batch 或 stop；保存建议，不自动启动下一轮 |

observations 每项为 evidence_ref、statement。hypotheses 每项为 statement、evidence_refs。limitations 是字符串列表。程序不证明自然语言与补丁语义一致，也不把假设提升为因果结论。

父策略 ID、current_policy_id 和 base_policy_id 必须相同。proposed_policy_id 必须不同。反馈轮次、批次、父模型、候选模型与调度输入必须相同。fixture 控制器检查点必须等于父检查点。批次必须存在于输入历史，其 policy_hash 必须匹配父策略。

set 仅允许以下路径：

- scoring.nll_preference、scoring.entropy_preference：完整对象。
- scoring.weights：完整三项权重。
- scoring.skill_preferences.<技能 ID>。
- batch_constraints.min_skill_token_shares.<技能 ID>。
- batch_constraints.min_task_type_token_shares.<已注册任务类型>。
- batch_constraints.max_task_type_token_shares.<已注册任务类型>。

add/remove 仅允许 eligibility.excluded_data_ids 和 eligibility.deferred_batch_ids 的字符串列表。程序按集合语义操作并排序输出。添加已有项和移除不存在项均保持原集合。同一元素同时 add/remove 或列表重复项会失败。取消最低配额使用 set=0，不提供任意 delete。

程序逐条显式处理白名单路径。它不执行任意对象路径、数组下标或生成代码。新策略必须完整重校验。任何失败均不修改父对象。空补丁允许保持数值与选择行为，但仍产生有新身份的策略快照。

recommendation 允许 accept、reject、hold。accept 必须对应当前 fixture 的 accepted，reject 必须对应 rejected。hold 允许任意状态。inconclusive 不能 accept，也不能冒充已证实的 reject。报告始终为 recommendation_only，不执行模型晋级或回退。

历史调度使用按时间顺序的 DispatchDecision JSON 数组，历史反馈使用 FeedbackFixture JSON 数组。历史调度引用必须已存在，不能引用当前或未来记录。历史证据使用 `<dispatch_id>:<evidence_id>`，并要求提供对应历史反馈。验收建议只能引用当前反馈中的 acceptance_result。

应用记录 `dispatch-application-v1` 包含新策略哈希、请求哈希、语义 diff 和 metadata_diff。后者记录 policy_id、parent_policy_id 和 created_by 的实际变化。调度身份和父策略来源由程序填写。

## 纯接口与下一阶段接入

```python
ontology = SkillOntology.parse(ontology_raw)
labels = tuple(parse_labels(item, ontology) for item in label_rows)
policy = parse_policy(policy_raw, ontology)
contract = ExperimentContract.parse(config_raw)
records = validate_dataset(trajectory_rows, contract)
result = select_with_policy(contract, records, labels, ontology, policy,
                            history, allow_synthetic_labels=True)
application = apply_dispatch(policy, dispatch, feedback, ontology, history)
```

上述模块均不写训练数据库。validate_selection 只校验，不组批。select_with_policy 返回 SelectionResult；batch 是既有 BatchManifest。其 context_id 绑定新上下文，fingerprint 语义保持。apply_dispatch 返回 DispatchApplication，不写文件。

validate_selection 返回 PolicySelectionContext。该类型继承 SelectionContext，绑定合同、模型、数据、标签、技能表、策略、评分和历史的完整身份。直接将它传给旧 build_batch 时，也会保留这些身份。原 SelectionContext 和旧入口的身份规则保持不变。

历史证据的限定名称不得与当前证据或其他历史证据重名。名称冲突会明确失败，不会静默覆盖已有引用。

未来 teacher 应输出同一标签接口，并通过显式重新编译或重新绑定更新轨迹。真实训练与双路验证应替换反馈 fixture，并从逐任务证据与既有 acceptance 模块获得结果；当前解析器会拒绝未声明的真实反馈格式。真实控制器应输出 DispatchDecision，再走同一白名单校验。当前应用器明确拒绝 model 控制器，接入时需增加可验证的执行身份规则。

SWE-smith、SWE-agent 等适配器未来可填写 task_ref、protocol_ref，并保留结构化 tool calls、call ID、工具返回和环境观察。当前没有这些数据的执行后端。自适应 NLL/entropy 刷新、关键 token 监督、模型接受与回退、多轮 RSI 和分布式训练均未实现。
