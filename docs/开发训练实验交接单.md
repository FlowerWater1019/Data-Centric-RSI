# 开发训练实验交接单

## 当前阶段

0.6.0 提供最小真实训练比较和基础片段诊断。工程验收不要求固定选择优于随机选择。工程验收要求数据、模型、预算、执行与结果可以核对。

下一阶段需要回答：在给定模型、候选池和训练预算下，固定选择是否比合格随机选择产生额外任务收益。

这个问题需要训练实验。继续增加 Agent 或自动晋级模块不能替代该实验。

## 需要研究者确定的信息

### 模型与设备

提供 27B 模型的具体名称、基座或指令版本，以及 H200 服务器上的本地目录。还需要目标服务器的连接方式，或由研究者在该服务器执行检查并返回结果。

不要先下载 27B 到本地。先读取模型配置，确认模型架构、分词器、模板和 LoRA 目标层，再决定加载方式。

8×H200 是目标硬件，不是当前已验证后端。当前执行器只支持单卡。目标模型的单卡可运行性尚未测量。若需要多卡，先实现对应后端，再进行工程验证。

### 数据与任务

确认首轮实验是否继续使用 MBPP。当前工程划分可验证流程，但不能直接代表目标能力与能力保持的研究划分。

正式开发协议应明确训练候选、评分参考、固定诊断、目标任务与保持任务。官方最终测试集继续隔离。若已有内部编程轨迹，可先提供小规模格式样本和验证规则，不需要立即迁移全部数据。

### 实验协议

在观察新实验结果前固定以下内容。

1. 冻结候选池、参考组、反馈任务和模型内容标识。
2. 冻结训练预算、学习率、LoRA 配置和种子列表。
3. 冻结代码输出协议、生成长度和任务失败处理方式。
4. 冻结主指标、保持指标、实际意义阈值和统计方法。
5. 冻结总体成本上限，以及继续或停止的判断规则。

默认 512 token 预算用于工程检查。它不是推荐的正式训练剂量。训练剂量需要在独立开发任务上校准。

## 首轮实验结构

| 分支 | 操作 | 作用 |
| --- | --- | --- |
| 未训练基线 | 不做更新，执行相同任务 | 给出模型起点 |
| 随机选择 | 从合格池排名并精确组批，再训练 | 测量普通微调收益 |
| 固定选择 | 使用冻结评分策略排名并精确组批，再训练 | 与随机组比较筛选额外差值 |

两组训练共享相同监督 token 总量。程序保留训练步数、上下文总量和耗时差异。多个配对种子使用同一任务集。不能把同一任务在多个种子下的结果当作全部独立的新任务样本。

如果两组批次相同，该运行不能识别数据选择作用。如果格式错误占据主要失败，应先完成独立的输出协议校准。如果差异区间很宽，应报告证据不足，并检查任务数量、预算与数据差异。

## 后续决策

首轮实验确认存在可测的选择差异后，再接入简单反馈规则与控制模型。随后增加经验使用、在线验收和按需评分。

若首轮实验没有支持额外收益，先检查候选池区分度、任务窗口、训练剂量和统计功效。不要直接把负结果归因于 Agent 尚未接入。

最终论文主张仍需独立的筛选评估。任务分数上升不能单独证明筛选能力上升。
