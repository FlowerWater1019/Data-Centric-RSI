# 工程检查与调整记录

本次检查覆盖当前源码、测试和工程文档。代码版本更新为 0.2.0。当前框架仍处于第一阶段，真实训练未接入。

## 1. 发现与修复

| 问题 | 影响 | 本次调整 |
| --- | --- | --- |
| 状态模块同时计算对照计划并保存数据库 | 计划规则难以独立测试 | 新增 comparison.py。状态模块保留状态检查和原子提交 |
| 命令行重复实现候选资格条件 | 后续修改可能使校验与筛选不一致 | 新增 inspection.py。两者共用 TrajectoryRecord.is_eligible |
| frozen 数据类仍包含可变字典 | 调用方修改输入可能改变已校验分数，或绕过内容一致性检查 | 配置与评分改为不可变字段类型。动态映射只读。原始轨迹以独立快照保存 |
| 批次、训练配置及评估接口使用无字段约束的字典 | 人工阅读时难以判断必填字段和返回结果 | 增加 BatchItem、TrainingConfig、EvaluationRequest、EvaluationResult 等明确类型 |
| 数据库先建表再检查版本 | 打开不支持的文件时可能已修改文件 | 新增 schema.py。现有库先检查，新库原子建表 |
| 状态读取使用写事务 | 读取可能争用写锁 | status 和 export 使用只读连接。snapshot 使用读事务 |
| 轨迹解析器承担多个校验步骤 | 局部规则难以定位 | 将质量、分词、监督、诊断、历史和评分分成命名函数 |
| 所有测试放在一个文件 | 失败定位和后续维护困难 | 按模块拆分测试，提取公共合成输入 |
| 错误编码与过大浮点数可能暴露底层异常 | 输入错误不能稳定转换为校验失败 | 统一转换为 ValidationError，并补充回归测试 |

不可变对象用于防止普通调用方的误修改。它不构成隔离不可信 Python 插件的安全机制。

## 2. 保持的行为

筛选公式、随机种子、质量条件、数据隔离、贪心组批和预算规则保持不变。重复请求仍返回原结果。失败与超额的真实成本仍保留。

命令参数保持不变。JSON 格式仍为 1.0。数据库版本仍为 1。本次无需迁移已有运行数据库。

内部 Python 接口有所变化。字段访问和后端返回类型的变化已记录在 [数据与接口说明](数据与接口说明.md) 中。

## 3. 验证结果

验证环境为 Windows 与 Python 3.12.3。全部检查使用 CPU。

执行命令：

```text
python -m unittest discover -s tests -v
```

当前共 70 项测试。原有 48 项行为测试保留，另增加 22 项检查。测试包括输入修改隔离、选择器返回内容校验、数据库兼容、只读访问、并发预算预留和独立进程命令流程。

独立进程检查覆盖 validate、init、plan-comparison、status、export 和 train。初始化与计划重复执行后，没有重复事件。train 仍明确返回退出码 2。

另对重构前的 local-verification-001 运行进行只读检查。当前状态与之前导出的报告一致。重新计算的计划与旧计划完全一致。计划哈希一致。数据库文件的字节校验值未变化。

没有执行真实分词、模型评分、LoRA 训练或任务测评。上述结果证明的是当前软件行为，不是数据筛选效果。

## 4. 当前限制

输入快照仍将完整数据保存在 SQLite 中。当前组批仍在保存计划的事务内计算。这适合现有小规模框架检查。接入大数据前，应改为外部不可变数据清单，并缩短写事务。

数据库检查覆盖版本、必要表和列。它不是任意损坏数据库的完整修复工具。

后端接口只有类型定义。产物校验、逐批成本记录、作业恢复和统计验收仍待接入。自动格式检查、完整静态类型检查和持续集成也尚未配置。
