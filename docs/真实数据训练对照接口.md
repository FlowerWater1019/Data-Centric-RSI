# 真实数据训练对照接口

## 数据流

```text
固定版本 MBPP
→ 参考解隔离检查
→ 来源记录与独立反馈任务
→ 分词、监督掩码和可选关键字诊断
→ 未评分的编译产物
→ 同一基座全量评分与固定参考百分位
→ 随机排名 / 固定排名
→ 相同完整轨迹组批器
→ 两个独立 LoRA 分支
→ 固定诊断与独立隔离任务
→ 微调收益 / 筛选额外差值
```

## 模块职责

| 模块 | 职责 |
| --- | --- |
| python_diagnostics | 从代码词法位置生成受版本控制的诊断片段 |
| data_compile | 校验导入清单，绑定模型与分词器，生成轨迹 |
| real_run | 校验开发配置，冻结真实输入，评分并登记对照计划 |
| scoring_run | 执行评分、保存调用意图和结果、登记成本 |
| packing | 在完整轨迹集合上求精确监督总量 |
| selection | 生成排名、校验配额、构建批次清单 |
| training_run | 执行冻结分支，恢复完整步骤，输出训练报告 |
| hf_backend | 执行模型前向、LoRA 更新、旁路诊断和完整检查点 |
| diagnostics | 按有效 token 聚合固定诊断集合，区分测量与缺失 |
| evaluation_run | 评估三个模型，并计算基线差值和选择差值 |
| reporting | 核验账本、产物和逐任务判定，生成开发报告 |

旧 `pilot` 仍负责合成输入准备。旧流程与真实流程共用训练执行器。数据库格式保持不变。代码改动会改变恢复身份，旧版本训练必须使用旧源码目录恢复。

## 配置版本

合同 `1.0` 继续使用原贪心组批。合同 `1.1` 必须明确填写 `selection.packing_rule`。

`greedy_v1` 保留原行为。`exact_ranked_v1` 要求 `allowed_shortfall=0`。旧合同不会被静默升级。

运行配置 `real-comparison-1` 只允许 `purpose=development`。真实数据入口生成的合同仍为 `draft`。`purpose=research` 的最终研究流程继续明确拒绝执行。

## 精确组批

例如，排名后的完整轨迹监督量为 6、5、4、3，预算为 8。贪心选择 6 后无法补齐。精确组批选择 5 和 3。程序保留两条完整轨迹。

程序先计算每个排名后缀可达到的 token 总量，再按排名逐项检查。若包含当前轨迹后仍可达到预算，则保留该轨迹。否则跳过。该规则求解排名成员向量的字典序最优解，不最大化效用值之和。

精确组批要求候选池已经按编号、重复组和内容去重。程序拒绝含重复候选的输入。程序不会重复采样或截断监督掩码。

搜索上限为 4096 条候选、1000000 个预算 token，并要求 `(候选数+1)×(预算+1)≤64000000`。上限约束后缀位集合的规模。超限时明确报错。

精确组批只求解监督总量。技能配额仍在组批后检查。配额失败不证明所有组合都不可行。程序不自动降低配额。

## 训练与诊断

两个分支使用相同种子和基座。每个分支重新创建 LoRA、优化器和调度器。每条轨迹执行一次优化器更新。训练目标不按诊断片段加权。

训练旁路保存更新前的片段 CE。固定反馈诊断在训练前和候选重新加载后运行。两者不能混成同一曲线：前者的数据随选择变化，后者的数据集合固定。

关键字标注仅用于检查诊断链路。语法标签不能直接替代研究技能标签。对于没有标注的技能，聚合结果为 `MISSING`，均值为 null。

监督 token 严格相同，不保证计算成本相同。程序记录每组上下文 token、更新次数和更新耗时。更新耗时不包含加载、检查点保存和独立评估。

## 状态与恢复

SQLite 冻结配置、评分输入、训练批次和成本。运行目录保存带哈希的产物。评分调用先保存意图。成功结果随后保存并记账。未完成调用可能有未知消耗，不能自动按零成本处理。

训练恢复只允许最新完整检查点。恢复要求账本步骤与检查点边界一致。中断步骤、缺失意图、旧检查点或已进入最终保存阶段均被拒绝。程序不重复反向传播已完成数据。

评分和评估目前采用失败后保留证据的方式。它们没有自动重试或逐任务断点恢复。扩大运行前，需要把这个边界纳入总预算。

## 当前完成边界

0.6.0 完成设计中的最小真实训练比较，并接入基础片段诊断。它可以支撑下一次开发实验。它尚未实现在线 Agent、经验学习、自动晋级、按需刷新、权重与经验交叉研究评估或分布式训练。

继续增加上述模块前，应先检查真实任务上是否存在可测的选择差异。该问题需要训练实验，不能通过新增软件模块回答。
