# 恢复与验收接口说明

本文对应 0.4.0。该版本增加三个工程能力：完整步骤恢复、独立纯函数任务评估、任务级配对判定。该版本不开放正式研究模式。

## 1. 训练恢复

例如，随机组有两条轨迹。程序训练第一条轨迹后保存检查点。进程可以在该位置退出。新进程从该检查点加载状态，只训练第二条轨迹。账本最终仍记录两条轨迹的实际监督量。

每个步骤按以下顺序执行：

1. 写入步骤意图文件。
2. 执行前向与反向传播。
3. 在同一数据库事务中记录成本和轨迹使用。
4. 更新优化器和学习率计划。
5. 将完整状态写入临时检查点目录。
6. 将临时目录发布为完整检查点目录。

状态包含 LoRA 参数、优化器状态、学习率计划、Python 随机状态、Torch 随机状态和 CUDA 随机状态。状态也包含已完成步骤、实际监督量和损失记录。加载使用 `weights_only=True`。该参数的范围见 [PyTorch 2.10 序列化说明](https://docs.pytorch.org/docs/2.10/notes/serialization.html)。

恢复必须使用原尝试编号、原数据顺序、原配置、原模型引用、原代码、相同依赖版本和相同 GPU UUID。程序还会复核本地模型文件。恢复回调使用原步骤编号。账本对相同消耗去重。

程序拒绝以下恢复请求：

- 检查点不是最新步骤。
- 检查点文件哈希不匹配。
- 存在尚未发布的步骤或检查点目录。
- 检查点与账本的步骤数不同。
- 原尝试已经失败或完成。
- 原预算预留已经关闭。
- 原运行正在被另一个进程修改。
- 训练已进入最终产物保存阶段。

步骤内中断可能发生在成本回写前。该部分成本可能未知。程序不重放该步骤，也不删除已经记录的成本。当前恢复保证针对本机文件系统上的完整进程边界，不包含断电恢复或网络文件系统。

`PAUSED` 是可见状态。它表示程序已发布检查点并主动退出。`RUNNING` 表示存在未结束尝试；异常退出时，该状态不能证明进程仍在运行。`COMPLETED` 只表示训练完成。

参数相等的验证只覆盖本次模型、设备和软件环境。不同平台和版本的数值复现范围见 [PyTorch 2.10 复现说明](https://docs.pytorch.org/docs/2.10/notes/randomness.html)。

## 2. 独立任务评估

`coding-tasks-1` 清单包含目标任务和能力保持任务。清单角色必须是 `feedback_execution`。程序拒绝 `final_test`。任务必须有独立编号、来源分组、重复分组、提示和非空测试用例。

当前执行器支持函数 `solve(x, y)`。函数体只包含一条 `return`。表达式支持整数、加减乘、整除、取余、比较、条件表达式，以及 `abs`、`min`、`max`。整数绝对值不得超过 `10^12`。代码、语法树和表达式深度均有上限。

解释器逐个处理允许的语法节点。模型文本不会传入 Python 的 `eval`、`exec` 或外部进程。当前执行器不是通用 Python 沙箱，不能运行 HumanEval、MBPP 或仓库级任务。

每个模型对每个任务执行一次贪心生成。提示包含任务说明和语法范围。提示不包含测试答案。基线、随机组和固定组使用同一任务清单。

逐任务证据保存生成代码、通过测试数、测试总数和执行状态。语法不支持、运行错误和答案错误均计为任务失败。任务失败仍属于分母。

`pass_at_1` 的分母是任务数。一个任务必须通过全部测试才能计为通过。任务内的多个测试用例不会增加统计样本量。

标识隔离检查能发现相同任务编号、相同来源分组、相同重复分组和完全相同文本。该检查不能证明语义无泄漏。真实数据接入时还需检查来源和近重复内容。

评估调用在发起前记账。失败调用仍占用预算。生成阶段异常会产生 `execution_error`，并保留已完成任务的证据。程序不把该错误转换为模型能力下降。

## 3. 配对判定

`acceptance-1` 是工程判定配置。它与研究合同中的验收字段分开版本管理。当前不允许重复检验。

例如，基线在某任务失败，候选在同一任务通过，该任务的差值为 `+1`。反向变化的差值为 `-1`。结果相同的差值为 `0`。程序按任务编号配对，然后分别计算目标组和能力保持组的平均差值。

当前规则对 `[-1, 1]` 的配对差值使用 Hoeffding 保守区间。每组半径为 `sqrt(2 * log(4 / alpha) / n)`。两个组共用一次比较的错误概率上限 `alpha`。该界以组内任务独立抽样为前提。手工编写的合成任务只检查计算流程，不能支持总体性能推断。

程序按以下规则判定：

1. 任一组任务数不足，返回 `inconclusive`。
2. 目标增益下界达到最低增益，且保持能力下界不低于负容忍值，返回 `accepted`。
3. 任一组区间上界仍不能达到对应阈值，返回 `rejected`。
4. 其余情况返回 `inconclusive`。

当前四道任务每组只有两道。示例规则要求每组至少 16 道。因此，示例应返回 `inconclusive`。16 是工程配置值，不是研究实验的统计功效结论。

随机组与固定组分别比较同一个基线。当前错误概率范围针对单次候选比较，不覆盖跨组选择、反复尝试或多轮 Agent 自适应决策。正式研究需要另行冻结多重比较规则和停止规则。

判定保存在独立评估报告中。它不会更新 `accepted_model`。自动晋级事务、保留集维护和多轮调用控制仍待实现。

## 4. 兼容性

原轨迹格式和合同格式仍为 `1.0`。数据库仍为版本 `1`。新增暂停和恢复信息使用已有事件表。旧版数据库不会自动添加检查点，因此不能恢复 0.3.0 的训练。

新增命令为 `resume-pilot` 和 `evaluate-pilot`。`pilot` 增加可选的 `--stop-after-step`。训练报告版本变为 `pilot-report-2`。新代码应识别报告版本，不能假设所有历史运行都支持恢复。
