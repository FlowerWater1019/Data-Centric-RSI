# 真实数据训练对照运行手册

公开仓库说明：机器地址、服务器账号和设备 UUID 使用占位值。路径需按目标机器填写。历史结果数字保持不变。

## 1. 使用范围

本手册适用于 0.6.0。框架运行单卡开发对照。两种选择器使用同一个模型起点、候选池、参考分布和训练配置。程序分别评估未训练基线、随机选择分支和固定选择分支。

本手册的默认值用于工程检查。512 个监督 token 不构成有统计效力的研究预算。开发结果不能直接作为最终论文结果。

程序支持已有的本地模型。程序不下载模型。当前已验证 Qwen2.5-0.5B-Instruct。27B、八卡 H200、多卡训练和其他模型架构仍未验证。

## 2. 环境

在 Linux 上执行隔离评估。环境需要 Bubblewrap、libseccomp 和系统 Python。隔离配置见 `configs/sandbox.json`。

训练环境的已验证依赖见 `pyproject.toml` 的 `hf` 部分。不要为此流程改动服务器的全局 Python 环境。

以下命令使用当前服务器已有环境。先进入代码目录。设置现有模型路径。将输出放入新的目录。

```bash
cd /data/TRAINING_USER/rsi-framework/20261018-v0.6.0
export PY=/data/TRAINING_USER/opd-if-research/.venv/bin/python
export MODEL=/data/TRAINING_USER/.cache/modelscope/hub/models/Qwen/Qwen2.5-0.5B-Instruct
export OMP_NUM_THREADS=1
export PYTHONPATH=.
export RUN=runs/development-001
mkdir "$RUN"
```

`mkdir` 失败时，使用另一个新目录。不要删除已有运行来复用名称。

## 3. 执行环境检查

先运行自动测试。

```bash
RSI_RUN_SANDBOX_TESTS=1 CUDA_VISIBLE_DEVICES='' "$PY" -m unittest discover -s tests -v
```

再运行隔离检查。

```bash
CUDA_VISIBLE_DEVICES='' "$PY" -m rsi sandbox-check \
  --config configs/sandbox.json --output "$RUN/sandbox-check.json"
```

任一步失败时，先处理失败。不要把隔离调用改成宿主执行。

## 4. 导入真实数据

原始 MBPP 文件已固定版本。现有服务器保留了该文件。也可按上一版数据入口手册获取同一版本。

```bash
CUDA_VISIBLE_DEVICES='' "$PY" -m rsi import-mbpp \
  --source /data/TRAINING_USER/rsi-framework/20261018-v0.5.0/runs/mbpp-import-v1/upstream.jsonl \
  --origin configs/mbpp.source.json \
  --sandbox-config configs/sandbox.json \
  --output "$RUN/imported" --limit-per-role 16 \
  > "$RUN/import.receipt.json" 2> "$RUN/import.log"
```

程序先冻结选择，再检查参考解。失败条目进入拒绝清单。程序不补选替代条目。官方测试集不执行。

从原始回执读取清单哈希。不要从终端折行文本手动复制哈希。

```bash
export BUNDLE_SHA=$("$PY" -c 'import json,os; print(json.load(open(os.environ["RUN"]+"/import.receipt.json"))["manifest"]["sha256"])')
```

## 5. 编译轨迹与诊断位置

```bash
CUDA_VISIBLE_DEVICES='' "$PY" -m rsi compile-data \
  --bundle "$RUN/imported" --bundle-sha256 "$BUNDLE_SHA" \
  --config configs/mbpp.engineering.json --model-path "$MODEL" \
  --output "$RUN/compiled" --max-length 1024 \
  --diagnostics python_keywords_v1 > "$RUN/compile.receipt.json"
```

编译会加载分词器并计算本地模型文件哈希。编译不加载 GPU 模型。超长轨迹会导致失败。程序不静默截断轨迹。

`python_keywords_v1` 标记控制关键字和 `return` 关键字。标注范围包含必要的前导空格。字符串和注释中的同名文字不标记。标签只表示语法位置，不证明控制流能力或返回值正确性。

诊断标注不改变文本、token 序列或训练掩码。`--diagnostics none` 可关闭标注。两个版本分别保存，不覆盖原数据包。

保存编译报告的哈希。

```bash
export COMPILED_SHA=$("$PY" -c 'import os; from rsi.artifacts import file_sha256; print(file_sha256(os.environ["RUN"]+"/compiled/report.json"))')
printf '%s\n' "$COMPILED_SHA" > "$RUN/compiled.sha256"
```

后续检查使用这个已保存的值。不要在检查失败后重新计算哈希来绕过内容变化。

## 6. 冻结训练配置

复制开发配置。

```bash
cp configs/comparison.development.json "$RUN/comparison.json"
```

默认配置包含以下值。

| 字段 | 默认值 | 含义 |
| --- | --- | --- |
| seed | 17 | 两组共享的随机种子 |
| supervised_token_budget | 512 | 每组实际监督 token 总量 |
| packing_rule | exact_ranked_v1 | 在精确总量下优先保留排名靠前的完整轨迹 |
| learning_rate | 0.0001 | 固定学习率 |
| lora_rank | 4 | LoRA 秩；alpha 为秩的两倍 |
| max_sequence_length | 1024 | 训练上下文上限 |
| precision | bf16 | 模型计算精度 |
| scoring_token_budget | 100000 | 基线评分与训练后诊断的总监督 token 上限 |

当前训练后端每条轨迹执行一次优化器更新。损失是该轨迹有效监督 token 的平均交叉熵。程序不使用梯度累积、重复采样或 token 截断。LoRA 固定作用于 `q_proj` 和 `v_proj`。

两组实际监督 token 总量严格相等。两组的轨迹条数、上下文总量和训练耗时可能不同。报告会保留这些差异。

检查输入与预算。

```bash
CUDA_VISIBLE_DEVICES='' "$PY" -m rsi check-comparison \
  --compiled "$RUN/compiled" --compiled-sha256 "$COMPILED_SHA" \
  --config "$RUN/comparison.json" > "$RUN/input-check.json"
```

`INPUTS_VALID` 表示结构与预算可达性通过。固定策略配额仍需真实评分后检查。

预算不可达时，不执行训练。研究者可在查看训练结果前，调整预算或扩展候选池，并创建新配置。不要以截断轨迹补齐预算。

## 7. 核对设备

先查看当前 GPU 信息和计算进程。

```bash
nvidia-smi --query-gpu=index,uuid,name,memory.used,memory.total --format=csv
nvidia-smi --query-compute-apps=pid,gpu_uuid,process_name --format=csv
```

确认目标设备可用后，绑定完整 UUID。以下 UUID 对应当前服务器已验证的第一张 RTX 5880。

```bash
export CUDA_VISIBLE_DEVICES=GPU-REPLACE_WITH_FIRST_DEVICE_UUID
```

运行入口会在加载模型前核对实际 UUID 和型号。不要把 `CUDA_VISIBLE_DEVICES=0` 当作等价写法。

## 8. 运行真实训练对照

```bash
"$PY" -m rsi run-comparison \
  --compiled "$RUN/compiled" --compiled-sha256 "$COMPILED_SHA" \
  --config "$RUN/comparison.json" --model-path "$MODEL" \
  --output "$RUN/training" --device cuda:0 \
  > "$RUN/train.receipt.json" 2> "$RUN/train.log"
```

程序依次完成全量评分、参考分布换算、两组精确组批、独立 LoRA 训练和固定诊断。两组分别从原始基座开始。固定组不加载随机组的候选。

查看训练状态。

```bash
"$PY" -m rsi status --db "$RUN/training/state.sqlite3" --run-id training
```

完成后，`training/report.json` 的 `training_status` 为 `COMPLETED`。`same_batch=true` 表示两组选择相同。此时没有数据选择差异，不能据此估计筛选额外收益。

## 9. 验证或恢复暂停

工程检查可在第 8 步增加 `--stop-after-step 1`。该选项在随机组第一个完整更新后暂停。暂停不会返还已消耗成本。

从原始暂停记录读取检查点位置和哈希。

```bash
export CKPT=$("$PY" -c 'import json,os; print(json.load(open(os.environ["RUN"]+"/training/pause.json"))["checkpoint"]["path"])')
export CKPT_SHA=$("$PY" -c 'import json,os; print(json.load(open(os.environ["RUN"]+"/training/pause.json"))["checkpoint"]["sha256"])')
"$PY" -m rsi resume-comparison \
  --output "$RUN/training" --model-path "$MODEL" --device cuda:0 \
  --arm random --checkpoint "$CKPT" --checkpoint-sha256 "$CKPT_SHA" \
  > "$RUN/resume.receipt.json" 2> "$RUN/resume.log"
```

恢复要求原源码、模型内容、设备、配置和完整检查点一致。程序恢复适配器、优化器、调度器和随机状态。程序不重复训练已完成步骤。

如果中断发生在更新过程中，程序可能无法确认最后一步成本。此时保留目录和日志。程序拒绝自动重放。评分中断、诊断中断和任务评估中断也不自动重试。新的尝试必须使用新目录，并保留原尝试的成本记录。

## 10. 执行隔离评估

训练完成后运行以下命令。

```bash
"$PY" -m rsi evaluate-pilot \
  --pilot "$RUN/training" --tasks "$RUN/imported/feedback_tasks.json" \
  --rule configs/acceptance.engineering.json --model-path "$MODEL" \
  --output "$RUN/evaluation" --device cuda:0 \
  --sandbox-config configs/sandbox.json --max-context-length 1024 \
  > "$RUN/evaluation.receipt.json" 2> "$RUN/evaluation.log"
```

命令名保留为 `evaluate-pilot`。该命令同时支持真实数据开发对照。每个模型对每道任务生成一次。每个测试在独立隔离进程中执行。

格式错误属于任务失败，并保留在任务分母中。基础设施错误导致运行失败。程序不会把基础设施错误写成模型测试失败。

输出协议要求纯代码，或一个没有外部说明文字的代码块。正式开发实验前，应在独立开发样本上检查格式错误与生成截断。冻结协议后，不得根据本轮结果放宽解析器。

## 11. 生成对照报告

```bash
CUDA_VISIBLE_DEVICES='' "$PY" -m rsi report-comparison \
  --training "$RUN/training" --evaluation "$RUN/evaluation" \
  --output "$RUN/summary"
```

阅读 `summary/report.md`。详细字段位于 `summary/summary.json`。

| 字段 | 解读 |
| --- | --- |
| sft_vs_baseline | 两个训练分支各自相对未训练基线的变化 |
| fixed_vs_random | 固定选择相对随机选择的额外差值 |
| batch_jaccard | 两组样本集合的交集大小除以并集大小 |
| training_costs | 每组实际监督量、上下文量、更新步数和更新耗时 |
| diagnostics | 同一固定诊断集的训练前后 CE；缺失片段标为 MISSING |

程序按任务配对。单道任务中的多个断言不增加统计样本数。现有 Hoeffding 区间较保守。区间只覆盖单次比较的两个任务组，不包含多个种子或多个比较的联合校正。

判定为 `inconclusive` 时，记录证据不足。不要将其写成接受或拒绝。程序不会晋级候选模型。

## 12. 进入开发训练实验前的条件

工程链路通过后，先冻结实验协议，再增加训练规模。需要确定以下信息。

1. 确定实际实验模型及其本地目录。
2. 确定训练候选池、反馈目标任务和能力保持任务。
3. 确定训练预算、随机种子列表和实际意义阈值。
4. 确定输出格式、生成长度、统计方法和失败处理规则。
5. 确定硬件运行方式，并完成该模型的显存检查。

当前 MBPP 目标组与保持组来自工程哈希划分，不代表经过验证的两类能力。关键字 CE 也不等于能力缺口。研究实验需要另外确认任务定义。

多个种子必须使用同一编译产物和评估任务。每个种子创建独立配置与新运行目录。不要只保留表现最好的种子。所有尝试、失败和实际成本均应保留。

27B 模型与 H200 训练配置需要在目标服务器验证。框架当前不支持八卡训练。不要把 `world_size` 改为 8 后直接执行。下一阶段先检验数据选择是否产生额外收益，再决定是否增加在线 Agent、多轮晋级和按需评分。
