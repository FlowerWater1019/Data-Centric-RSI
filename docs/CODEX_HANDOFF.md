第二阶段新增独立单次训练与双路验证。接手该流程时，先读 [单次训练与双路验证接口](单次训练与双路验证接口.md)、[运行手册](单次训练与双路验证运行手册.md) 和 [训练验证服务器交接](训练验证服务器交接.md)。下文的 0.6.0 对照流程仍保留。第二阶段的本机 mock 结果不代表目标模型适配已完成。

## 1. 接手任务

你正在接手 Data-Centric-RSI 的训练端工作。当前代码版本为 0.7.0。

首项任务是在目标机器上核对环境、适配目标模型，并完成小规模真实数据训练对照。随后按明确配置执行开发实验。项目目标模型预计为 27B，目标设备预计为 8 张 H200，每张显存 144 GB。实际型号、可用设备和模型目录必须从本机核实。

当前系统可以运行单轮比较。随机选择和固定选择共用评分、完整轨迹组批、单卡 LoRA 训练与任务评估组件。Agent 自动调整、经验学习、模型自动晋级、按需评分和分布式训练尚未实现。

8. 按实际需求实现模型适配。若确需多卡，先实现后端，再补充测试和小规模验证。

不要仅因需要补代码就把任务退回项目负责人。可自行处理的工程问题应继续处理。缺少模型来源、可用设备权限或实验预算等外部信息时，再列出具体缺项。

## 4. 保持的实验约定

- 原始模型只评估，不训练。
- 随机组和固定组从同一个原始模型开始。
- 两组使用同一候选池、同一评分参考组和相同监督 token 总量。
- 程序选择完整轨迹，不截断代码来凑齐监督量。
- 两组共用训练配置。实际上下文量、更新次数和耗时分别报告。
- 三个模型执行同一批独立反馈任务。
- 最终测试集不进入筛选、诊断或验收。
- 所有失败调用和已发生成本均保留。
- 诊断 CE 只作为辅助信号，不能替代任务通过率。
- 多个种子按预先配置的列表运行，不只保留最好的种子。

当前开发配置只给出工程检查值。训练量 512 token、学习率 0.0001、LoRA 秩 4、上下文 1024 均未在目标 27B 上验证。研究配置缺失时，不自行把这些值当作正式实验参数。

## 6. 获取固定版本的数据

仓库只包含小规模合成示例，不包含真实数据和模型。MBPP 来源与 SHA256 固定在 [configs/mbpp.source.json](../configs/mbpp.source.json)。

以下命令在 Linux 仓库根目录执行。`python` 必须指向已核对的本机 Python 环境。目标文件若已存在，命令会拒绝覆盖。

```bash
mkdir -p runs/source
python - <<'PY'
import hashlib
import json
from pathlib import Path
from urllib.request import urlopen

origin = json.loads(Path('configs/mbpp.source.json').read_text(encoding='utf-8'))
target = Path('runs/source/mbpp.jsonl')
if target.exists():
    raise FileExistsError(target)
with urlopen(origin['url'], timeout=60) as response:
    content = response.read()
if hashlib.sha256(content).hexdigest() != origin['sha256']:
    raise ValueError('MBPP SHA256 mismatch')
with target.open('xb') as handle:
    handle.write(content)
print(target)
PY
```

若目标机器不能联网，由执行者从允许的来源转入同一文件。仍须校验原 SHA256。后续导入使用 `--source runs/source/mbpp.jsonl`，不引用旧服务器的文件。

## 7. 执行顺序

1. 完成当前代码的测试与隔离检查。
2. 完成目标模型的小规模兼容与显存检查。
3. 在独立开发样本上检查输出格式和生成长度。
4. 固定数据角色、训练预算、种子列表、生成协议和统计规则。
5. 执行 import-mbpp 和 compile-data。
6. 执行 check-comparison，确认输入与预算可达性。
7. 执行 run-comparison，训练两个独立分支。
8. 执行 evaluate-pilot，评估原始模型与两个候选。
9. 执行 report-comparison，生成微调收益和筛选额外差值报告。
10. 核对实际成本、失败记录、模型产物和设备资源释放。

当前 world_size=8 会被执行器拒绝。`configs/h200_8gpu.draft.json` 是待适配草稿。当前后端没有梯度累积、梯度检查点或八卡执行能力，不要假定存在这些功能。

完整步骤检查点可以恢复。步骤内中断、评分中断和评估中断不能盲目重跑。先检查账本与原始日志，再判断能否继续。

恢复训练还要求源码身份一致。0.7.0 改变了源码位置和清单。需要恢复旧运行时，使用该运行对应的旧提交和原运行目录。不要修改清单来绕过检查。

## 8. 完成标准与回传

第一阶段完成标准是：目标模型在实际设备上完成一轮可核对的小规模对照，并保留全过程证据。结果可以为证据不足，不要求固定组获胜。

输出至少包括以下文件或目录。它们保存在本机运行目录，不上传 GitHub。

- 环境和目标模型检查记录。
- 实际使用的配置、种子、数据来源和编译清单。
- 两组所选样本与实际监督量。
- 训练、诊断、评估状态库和日志。
- 逐题原始生成与测试结果。
- 汇总 report.md 和 summary.json。
- 模型、适配器、检查点和优化器状态的本机路径。

如果修改了代码，按本仓库工程约定补充测试和运行说明。提交前检查暂存区，确保没有数据、模型、状态库、日志或凭据。
