# 训练验证服务器交接

本机已完成 CPU mock 编排验证。真实 tiny 集成测试已提供。目标机器与 27B 模型尚未验证。历史 0.6.0 的服务器记录不能代替本次设备检查。

## 接手顺序

1. 读取 AGENTS.md、CODEX_HANDOFF.md 和单次训练接口、手册。
2. 记录当前提交、Python、torch、CUDA、transformers、peft、tokenizers、safetensors 和操作系统版本。
3. 检查本机模型目录的 config.json、架构、权重和聊天模板。
4. 使用文件哈希与实际 tokenizer 创建 ModelRef 和 ModelLocation。
5. 检查 adapter rank、targets、alpha 和 dropout。无 adapter 时明确声明 none。
6. 使用 nvidia-smi 获取授权单卡的完整 UUID、型号和可用显存。
7. 设置 CUDA_VISIBLE_DEVICES 为该完整 UUID。命令使用逻辑 cuda:0，并传实际 --expected-gpu-name。
8. 在已有隔离依赖环境运行完整单元测试及真实 tiny 测试。
9. 对 Python 任务执行 sandbox-check。无法启用 Bubblewrap/seccomp 时停止该执行后端。
10. 在授权预算内执行小规模 hf_local 编译、冻结训练与双路验证。
11. 检查实际 adapter 更新、父文件未变、候选重新加载、成本和步骤恢复。
12. 单独执行 final_test，保存最终报告与反馈套件隔离依据。

`configs/training_server.template.json` 只列待核验项。它不通过任何运行配置解析器。不要填虚假的 UUID、架构或模型路径。当前执行器只有单卡能力，不能把八卡硬件草稿当作多卡实现。

## 仍需负责人确定的实验协议

正式数据版本、问题级划分、主指标、训练 token 预算、评分预算、任务调用预算、种子列表和机械验收阈值均需明确配置。合成示例中的 136 token、学习率、rank 和任务数只是 smoke 值。

最终测试不得进入选数、拟合、策略更新或验收。技能片段拟合只计算固定监督位置的差异，不能替代独立任务成功率。任务技能标签不提供失败原因的因果证据。

当前验收规则只对应一次预设父候选比较。多轮重复检验、控制器权限、模型接受事务和接受后样本禁用事务属于后续阶段。

## 回传内容

回传提交号、运行命令、环境版本、实际模型架构和已核验 GPU 信息。回传完整测试通过与跳过项。回传 plan、环境、成本和报告摘要，以及文件清单哈希。说明父 adapter 是否保持不变、候选是否实际更新和重新加载、恢复是否与连续训练一致。

权重、优化器、数据库、私有样本和详细生成记录保留在运行机器。提交前检查暂存区。不使用强制添加绕过 runs 忽略规则。当前阶段不接控制 Agent，不自动晋级，不循环选数。
