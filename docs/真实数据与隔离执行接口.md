# 真实数据与隔离执行接口

本文对应 0.5.0。新增流程是“固定真实数据来源 → 保留官方划分 → 检查参考解 → 编译轨迹 → 独立生成 → 隔离测试”。当前流程用于工程验证，不自动晋级模型。

## 1. 数据来源与划分

首个适配器支持 Google Research 发布的原始 MBPP JSONL。配置 `configs/mbpp.source.json` 固定来源 URL、完整提交号、文件 SHA256 和许可声明。导入命令不会联网下载。原始代码只在隔离环境中执行，不在宿主 Python 中执行。

[MBPP 官方说明](https://github.com/google-research/google-research/blob/f82046ba5aabbbb427dbfd38a254d26bff08b533/mbpp/README.md)规定以下划分：

| 官方任务编号 | 官方用途 | 当前工程用途 |
| --- | --- | --- |
| 1–10 | 提示示例 | 排除 |
| 11–510 | 测试 | 保留在原始归档中，不执行，不编译为训练轨迹 |
| 511–600 | 验证 | 分为工程目标任务和能力保持任务 |
| 601–974 | 训练 | 分为候选、参考和反馈诊断来源 |

数据许可来自 [官方仓库声明](https://github.com/google-research/google-research/blob/f82046ba5aabbbb427dbfd38a254d26bff08b533/README.md)，为 CC BY 4.0。引用数据时应保留来源与作者归属。

导入要求完整的 974 条原始记录。程序先做划分和重复检查，再取工程子集。`--limit-per-role` 是工程规模上限，不会改变官方划分。

程序连接规范化提示相同或代码语法树相同的条目。重复组跨越官方划分时，训练或反馈副本会被排除。同一划分中的重复组只保留一个代表。该规则不能识别所有语义近重复。

角色分配使用重复组标识的稳定哈希。训练组的十个哈希桶中，一个桶作为参考，一个桶作为反馈诊断，其余桶作为候选。验证组按哈希奇偶分为目标组和能力保持组。这个划分用于接口检查，尚未定义研究所需的技能分层和保留能力集合。

## 2. 参考解检查与监督范围

程序在执行前保存选中编号。随后对每个参考解执行原始 `test_list`。每条测试使用独立隔离进程。`challenge_test_list` 保留在原始归档中，本版本不执行。

全部原始测试通过后，训练侧记录才进入 `sources.jsonl`。参考解语法错误、入口不明确或测试失败时，条目进入 `rejected.json`。程序不会用其他条目替换失败条目。隔离机制故障会终止导入，并保存 `failure.json`。

“valid”只表示参考解通过本次已记录测试。它不表示算法对所有输入都正确。`leakage=clear` 对应本适配器的官方划分和重复检查，不代表完成了语义泄漏审计。

每条来源记录使用现有 `source-1` 格式。用户消息包含任务描述和函数签名。assistant 消息包含经测试的参考代码。测试答案不会写入用户消息。

当前 MBPP 数据是单轮代码任务，不是工具调用轨迹。技能标签暂为 `python_codegen`。诊断片段为空，程序不会自动捏造关键能力片段。多轮修复轨迹和细粒度技能标注仍需后续接入。

## 3. 轨迹编译

`compile-data` 先检查导入清单及其文件哈希。随后加载本地 tokenizer，绑定模型、分词器与模板的内容标识，并调用已有 `compile_trajectory`。

编译器只监督有效 assistant 内容。模板、用户内容和跨边界 token 不进入损失。轨迹超长或位置映射无效时，编译失败。程序不截断轨迹，也不输出部分成功的轨迹包。

输出包括 `contract.json`、`trajectories.jsonl`、`model_identity.json` 和 `report.json`。轨迹可直接交给现有 `init` 与数据校验命令。评分保持为空，报告明确写入 `NOT_COMPUTED`。编译不会运行训练。

## 4. 隔离后端

`BubblewrapExecutor` 支持 Linux x86_64 上的 Python 标准库计算任务。函数可以使用循环、递归、类、列表、字典和标准库。当前不支持安装依赖、网络、文件写入、子进程、线程、GPU 或多语言工具链。

后端使用服务器已有的 Bubblewrap。它创建独立的用户、挂载、进程、网络、IPC 和主机名命名空间。它只以只读方式挂载 `/usr` 和可信启动器。用户主目录、项目目录、模型目录和凭据不挂载。环境变量被清空。模型代码不能访问宿主 GPU。

Bubblewrap 的保护范围取决于调用参数，不能仅凭安装了该工具就认定环境安全。依据见 [Bubblewrap 官方安全说明](https://github.com/containers/bubblewrap#sandbox-security)。当前参数由 `sandbox_command` 统一生成，不接受任意挂载参数。

可信启动器先设置资源上限，再加载 seccomp 系统调用允许列表，最后执行代码。列表允许 Python 计算和只读文件访问。列表不允许创建进程、创建套接字、执行外部程序、挂载文件系统或提高资源上限。seccomp 的系统调用过滤范围见 [Linux 接口说明](https://man7.org/linux/man-pages/man2/seccomp.2.html)。

默认限制如下：

| 资源 | 默认限制 | 执行位置 |
| --- | --- | --- |
| 墙钟时间 | 每测试 5 秒 | 沙箱外父进程 |
| CPU 时间 | 软上限 2 秒，硬上限 3 秒 | 内核资源限制 |
| 虚拟地址空间 | 每进程 256 MiB | 内核资源限制 |
| 输出 | 每测试 64 KiB | 沙箱外父进程 |
| 新进程和线程 | 禁止 | 系统调用过滤 |
| 新文件写入 | 禁止 | 只读挂载、打开标志过滤、文件大小限制 |

超时或输出超限时，父进程终止沙箱。当前限制是虚拟地址空间上限，不是容器总物理内存计量。禁止新进程和线程使候选代码保持单进程。该环境共享宿主 Linux 内核，不等同于虚拟机。

当前 Python 测试与候选代码在同一个隔离进程内运行。该设计保护宿主环境，但不保证抵抗候选代码蓄意篡改测试逻辑。验收结果不会自动晋级模型。正式对抗评估还需独立判题协议或更强的外部验证。

## 5. 启动探针与错误分类

`sandbox-check` 检查标准库执行、宿主目录隐藏、网络禁止、新进程禁止、文件写入禁止和资源上限不可提高。任一探针失败时，程序拒绝执行候选代码。Windows 或缺少隔离依赖的环境也会明确拒绝，不会退回普通宿主 Python。

测试断言失败、候选运行错误、内存超限、超时和输出超限都属于任务失败。隔离启动失败属于基础设施错误，会终止本次评估。后者不能被解释为模型能力下降。

每次测试启动前保存 `.started.json`。完成后保存 `.result.json`。发生中断时，调用痕迹仍保留。训练侧参考解验证和模型侧任务评估分别记录测试调用，不复用测试进程。

## 6. 通用任务评估

新增任务格式为 `python-tasks-1`。任务包含提示、函数入口、初始化代码、断言测试、来源分组和重复分组。格式只接受 `feedback_execution` 角色，拒绝 `final_test`。

`evaluate-pilot` 按任务格式选择执行器。原来的 `coding-tasks-1` 仍使用受限整数解释器。`python-tasks-1` 必须提供 `--sandbox-config`。基线、随机组和固定组共用相同任务与限制。

生成提示只包含任务描述、签名和环境约束。测试答案和参考解不会发送给生成模型。每次生成的代码会先保存，再逐测试执行。代码允许为纯代码或单个 Python 代码块。当前代码提取上限为 8192 字符。

通过率继续使用任务作为分母。一个任务必须通过全部测试才能通过。格式错误也计入任务失败。每组少量工程任务不能支持研究结论。

`evaluation_calls` 继续计量任务生成尝试。隔离测试调用数量另记在逐任务证据中。二者不能相加后称为训练 token 或 GPU 成本。

## 7. 当前边界

数据包已经可以编译并写入状态接口。原 `pilot` 仍要求合成候选具有相同监督长度。不要把真实数据直接替换进该命令，也不要通过截断来凑齐监督预算。

下一步应接入真实数据评分、变长轨迹组批和等监督预算对照。随后再接入已有适配器起点与晋级事务。当前版本没有执行真实数据 SFT，也没有开放正式研究模式。
